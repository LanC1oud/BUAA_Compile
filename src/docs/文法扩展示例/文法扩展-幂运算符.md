# 文法扩展方案：幂运算 `**`

状态：修改建议，尚未实施。本文通过一个新的表达式层展示优先级、结合性、常量折叠和扩展诊断的联动。返回[示例目录](README.md)。

## 1. 规则与语义

新增 `PowerExp`，并用以下定义**替换**原 `MulExp`：

```text
PowerExp -> UnaryExp | PowerExp '**' UnaryExp
MulExp -> PowerExp | MulExp ('*' | '/' | '%') PowerExp
```

本例采用与仓库 `testgen/examples/power.ebnf` 一致的规则：

| 项目 | 本例约定 |
| --- | --- |
| 优先级 | 单目运算高于 `**`，`**` 高于 `* / %`，再到 `+ -` |
| 结合性 | 左结合：`2 ** 3 ** 2` 为 `(2 ** 3) ** 2`，结果 64 |
| 单目交互 | `-2 ** 2` 为 `(-2) ** 2`，结果 4 |
| 类型 | 两侧必须为相同基本类型，结果沿用该类型；不隐式混用 int / char |
| 值域 | 指数必须非负；`0 ** 0` 定义为 1 |
| 溢出 | int 运算按 Java int 的 32 位环绕；char 结果按 `& 0xFF` 截断 |
| 副作用 | 幂运算本身无副作用；操作数是否带副作用由其它已启用文法决定 |

左结合是本方案有意选定的规则，并不代表数学或其它语言的惯例。若希望右结合，必须同时改为 `PowerExp -> UnaryExp ['**' PowerExp]`、更换 AST 右子树类型、递归解析右操作数，并同步参考文法和测试；不能只把循环写成递归。

负指数约定：能证明是编译期常量的负指数在前端报扩展错误 `p`；不能静态确定的指数允许通过前端，未来运行时必须检查负值并按语言约定报错。本方案不把所有动态指数都拒绝。

## 3. 词法修改

`TokenType` 枚举增加：

```java
Power("POW"),
```

在 `Lexer.readOp()` 的 `switch (c)` 中增加：

```java
case '*' -> {
    int next = reader.read();
    if (next == '*') {
        addToken(TokenType.Power, "**", start);
    } else {
        reader.unread(next);
        addToken(TokenType.Mult, "*", start);
    }
}
```

继续保留 `Symbols.TABLE` 的单字符 `*` 映射。新增专门分支会优先处理该字符。`***` 应切为 `POW **`、`MULT *`，然后由语法阶段拒绝缺操作数的形状；不能为了接受输入而回退成三个乘号。

## 4. AST 与解析代码

### 4.1 新增 `PowerExp.java`

```java
package frontend.ast.expression;

import frontend.token.Token;

public class PowerExp extends BinaryExp {
    public PowerExp(UnaryExp operand) {
        super(operand);
    }

    public PowerExp(PowerExp left, Token op, UnaryExp right) {
        super(left, op, right);
    }

    @Override
    protected String getName() {
        return "<PowerExp>";
    }
}
```

### 4.2 调整 `MulExp` 两个构造器

保留现有包名、import 和 `getName()`，构造器改为：

```java
public MulExp(PowerExp operand) {
    super(operand);
}

public MulExp(MulExp left, Token op, PowerExp right) {
    super(left, op, right);
}
```

### 4.3 `Parser` 中的两个完整方法

```java
private PowerExp parsePowerExp() {
    PowerExp exp = watch(new PowerExp(parseUnaryExp()));
    while (among(TokenType.Power)) {
        Token op = consume(TokenType.Power);
        exp = watch(new PowerExp(exp, op, parseUnaryExp()));
    }
    return exp;
}

private MulExp parseMulExp() {
    MulExp exp = watch(new MulExp(parsePowerExp()));
    while (among(TokenType.Mult, TokenType.Div, TokenType.Mod)) {
        Token op = consumeAny(TokenType.Mult, TokenType.Div, TokenType.Mod);
        exp = watch(new MulExp(exp, op, parsePowerExp()));
    }
    return exp;
}
```

在 `Parser` 中引入新类；若当前使用表达式包的通配 import，无需再加单独 import。`atExpressionStart()` 无需增加 `Power`，因为 `**` 不是前缀运算符。

`watch()` 必须同时记录叶子层和每次左结合扩展。实施后，即使旧程序只有 `1 + 2`，其语法轨迹也会新增 `<PowerExp>`。这是输出契约变化，应更新参考答案；不能为了让旧答案通过而随机省略该标签。

## 5. 语义分析代码

### 5.1 增加分派

在 `Traverser.analyzeOperand()` 的 `node instanceof BinaryExp` 分支内部、最终 `return null` 前增加：

```java
if (node instanceof PowerExp power) {
    return analyzePowerExp(power, constContext);
}
```

保留其它层的分派。只新增 AST / parser 而忘记此处，会使类型检查在新节点处中断。

### 5.2 复用 `analyzeBinary()`（建议）

`PowerExp` 继承 `BinaryExp`，类型规则也与现有乘法一致：叶子传递操作数类型，非叶子要求两侧为同一种基本类型，结果沿用该类型。因此可以直接复用 `analyzeBinary()`；新增语法优先级层并不要求重写语义分析逻辑。

`analyzePowerExp()` 的完整方法只需：

```java
private Type analyzePowerExp(PowerExp exp, boolean constContext) {
    return analyzeBinary(exp, false, constContext);
}
```

第二个参数 `false` 表示不强制将结果改成 int，允许 char 操作数产生 char 结果。通用方法也已负责空值、缓存、递归分析、叶子传递和通过 `put()` 设置字符截断标记，无需重复。

不过，当前 `analyzeBinary()` 只检查类型，没有本文新增的“常量指数不能为负”规则。为保留扩展错误 `p`，在该方法**非叶子分支**算出 `result` 后、最终 `put(node, result)` 之前加入以下代码：

```java
if (result != null && binary instanceof PowerExp) {
    Integer exponent = isCompileTimeValue(binary.getRight())
            ? ConstFolder.fold(binary.getRight()) : null;
    if (exponent != null && exponent < 0) {
        errors.add(ErrorType.InvalidPowerExponent, binary.getOp().location());
        return null;
    }
}
```

该位置上左右子节点已分析并绑定符号，`result != null` 确保类型检查已经通过。此检查只针对 `PowerExp`，保留其它二元运算行为及原来的最终 `put(node, result); return result;`。

不要先在包装方法中调用 `analyzeBinary()`，再发现负指数后直接 `return null`：通用方法已经把该节点的成功类型放进 `types`，后续 `analyzeOperand()` 可能直接命中缓存，绕过拒绝结果。把定义域检查放在最终缓存写入前，可以让错误节点不被当作成功分析结果缓存。

此前独立展开的写法主要是为了不改通用方法，把类型检查和幂定义域检查一起放在专用方法中；这种组织也能工作，但会重复二元分析逻辑。若坚持让通用方法完全不包含运算符特例，可以保留独立实现，或者另提取一个定义域校验方法，在通用方法写缓存前调用。两种组织方式选一种即可，不要对同一节点重复执行检查。

叶子节点必须原样传递类型，通用方法在 `resultIsInt == false` 时已做到这一点。普通数组变量在传参途中也会经过该层；若对每个叶子都强制要求基本类型，会破坏旧语言中合法的数组实参。

### 5.3 只对真正的常量指数做静态拒绝

当前某些全局 / 静态变量也保存了初始化值，直接对任何指数调用 `ConstFolder.fold()` 可能误把可变变量的初值当成恒定值。例如全局 `int n = -1;`，进入 `main` 后先执行 `n = 2;`，随后 `2 ** n` 不能仅凭初值报 `p`。

可在 `Traverser` 增加以下保守判定。它在子节点完成语义绑定后使用，只接受纯常量结构；`Number` 使用本文件已有的显式 `frontend.ast.expression.Number` import：

```java
private boolean isCompileTimeValue(ASTNode node) {
    if (node instanceof Number) {
        return true;
    }
    if (node instanceof Exp exp) {
        return isCompileTimeValue(exp.getAddExp());
    }
    if (node instanceof ConstExp exp) {
        return isCompileTimeValue(exp.getAddExp());
    }
    if (node instanceof LVal lval) {
        return lval.getSymbol() != null
                && lval.getSymbol().isConst()
                && (lval.getIndex() == null || isCompileTimeValue(lval.getIndex()));
    }
    if (node instanceof BinaryExp binary) {
        return isCompileTimeValue(binary.getLeft())
                && (binary.isLeaf() || isCompileTimeValue(binary.getRight()));
    }
    if (node instanceof UnaryExp unary) {
        return switch (unary.getKind()) {
            case Primary -> isCompileTimeValue(unary.getPrimary());
            case Unary, Cast -> isCompileTimeValue(unary.getOperand());
            default -> false; // 调用，以及未来可能加入的自增等副作用形态
        };
    }
    if (node instanceof PrimaryExp primary) {
        return switch (primary.getKind()) {
            case Number -> true;
            case LVal -> isCompileTimeValue(primary.getLVal());
            case Paren -> isCompileTimeValue(primary.getExp());
        };
    }
    return false;
}
```

无法折叠时不伪造指数值；已有名字、类型等错误交给对应检查。此方案不包含跨语句常量传播，像局部变量 `n` 即使刚被赋成 `-1` 也不在这里强行推断。

### 5.4 扩展错误

在 `ErrorType` 增加 `InvalidPowerExponent("p")`，在 `DisplayError.chineseDescription()` 的 switch 增加：

```java
case InvalidPowerExponent -> "幂运算的常量指数不能为负数";
```

`p` 是扩展协议，不是官方 `a`～`n` 中的错误。现有 `priority()` 的 default 可为其提供语义错误优先级，不用改官方码。若同时采用自增方案，保留其 `o`，不要占用同一个码。

## 6. 常量求值代码

在 `ConstValue.calculate()` 的 switch 增加：

```java
case Power -> powInt32(left, right);
```

在同一类增加以下完整方法：

```java
private static int powInt32(int base, int exponent) {
    if (exponent < 0) {
        throw new IllegalArgumentException("负指数没有本语言定义的整数幂值");
    }
    int result = 1;
    int factor = base;
    int remaining = exponent;
    while (remaining != 0) {
        if ((remaining & 1) != 0) {
            result *= factor;
        }
        remaining >>>= 1;
        if (remaining != 0) {
            factor *= factor;
        }
    }
    return result;
}
```

不要用浮点 `Math.pow()` 再强转，否则大整数的取整和溢出行为与上述 int 规则不同。外层 `BinaryExp.calculateConst()` 已负责字符截断。`ConstFolder` 会吞掉求值异常并返回 null，因此仅在求值函数里抛异常**不会自动产生 `error.txt`**；第 5 节的显式诊断不可省略。

未来后端还需明确左、右操作数的求值顺序，并对动态负指数实现相同的定义域约束。当前项目没有后端，本文不给出已经可执行的运行保证。

## 7. 完整样例与预期

```c
const int k = 2 ** 3 ** 2;
int main() {
    int a[k];
    int x = 2 * 3 ** 2;
    printf("%d %d", k, x);
    return 0;
}
```

实施后应满足：`k` 的常量值为 64，数组长度为 64，`x` 的初始化表达式按优先级得到 18；每个 `**` 在 `lexer.txt` 中是一条 `POW **`，`parser.txt` 包含新增 `<PowerExp>`，`error.txt` 为空。

```text
1 k ConstInt
2 a IntArray
2 x Int
```

上方为 `symbol.txt` 预期；符号输出本身不展示数组长度，长度 64 必须通过 AST / 符号内部属性另行断言。未来运行输出应为 `64 18`。

独立负指数反例：

```c
int main() {
    int x = 2 ** (-1);
    return 0;
}
```

预期 `error.txt` 为 `2 p`。若尚未采用本文的新错误枚举，不能宣称该预期已经可用。

## 8. 边界测试表

| 输入 / 场景 | 核查点 |
| --- | --- |
| `2 ** 3 ** 2`、`2 ** (3 ** 2)` | 左结合 64；显式右嵌套 512 |
| `-2 ** 2`、`-(2 ** 2)`、`2 * 3 ** 2 + 1` | 4、-4、19，区分单目与乘加层 |
| `0 ** 0`、`0 ** 1`、`7 ** 0`、`(-1) ** 3` | 1、0、1、-1 |
| `2 ** 31`、`2 ** 32`、`1 ** 2147483647` | 最小 int、0、1；指数极大时不能线性循环 |
| `const int n = -1;` 后使用 `2 ** n` | 常量绑定后产生 `p` |
| 可变全局 `n` 初值为负，随后赋正值再作指数 | 不凭可变初值静态报 `p` |
| `2 ** (char)3`、整个数组作幂操作数 | 基本类型不一致 / 非基本类型，报 `e` |
| `(char)2 ** (char)8`、`(int)((char)2 ** (char)8)` | 内层 char 结果为 0；转 int 后仍为 0 |
| `2 * * 3`、`2 *** 3`、文件末尾 `2 **` | 不合并隔开的 token；非法结构能拒绝并结束 |
| `2 ** /* comment */ 3`、原有 `/*...*/` | 运算符与注释互不破坏 |
| 长 `**` 链、多层括号、与 `++` 混用 | AST 结构、深度、未来副作用求值次序 |

## 9. 与已有测试生成器衔接

仓库已有演示文件，可在编译器实施前独立生成前端参考数据：

```powershell
python -m testgen --rules testgen/examples/power.ebnf --replace --focus PowerExp --tokens testgen/examples/power-tokens.json --semantics testgen/examples/power-semantics.json --count 20 --seed 42 --out build/power-example
```

`--replace` 不可省略，否则原 `MulExp -> UnaryExp` 与新层并存会形成另一份规则。现有配置 `{"operators":{"**":"same"}}` 只表达同型基本类型规则，**尚不实现本文的静态负指数检查、扩展错误 `p` 或整数幂值验证**。生成器里的程序可能含负的常量指数，采用本文方案后需要同步扩充 oracle 并筛选 / 标记这些输入，再把该批输出作为完整契约的答案。

新增 `PowerExp` 目前不应使用 `--hide PowerExp`，因为本文 Java 方案会真实输出该层。需要把表中的确定性用例加入 `testgen/boundaries.py`，用独立断言验证数值与 `p` 的行号；不能仅靠随机生成的候选式覆盖来判断优先级、溢出及定义域正确。
