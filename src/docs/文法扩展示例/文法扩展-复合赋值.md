# 文法扩展方案：复合赋值 `+=`

状态：修改建议，尚未实施。本例添加一种语句，展示 token 识别、赋值判别、左值检查及副作用边界。返回[示例目录](README.md)。

## 1. 规则与语义

向已有 `Stmt` 增加一个候选式，保留其它候选式：

```text
Stmt -> LVal '+=' Exp ';'
```

本方案只增加 `+=` 语句，不增加赋值表达式，也不自动加入 `-= / *= / /= / %=`。

- 目标必须是可修改的 `int` / `char` 标量变量或数组元素，不能是常量、整个数组或函数。
- 左右两侧必须是相同基本类型，沿用当前工程的严格类型规则。`int x; x += 1;` 合法；`char c; c += 1;` 报 `e`，可以改用 `c += (char)1;`。
- 把目标的旧值与右侧值相加，再存回同一目标；int 环绕及 char 截断与已有加法规则一致。
- 左值的地址与下标只计算一次。未来运行时顺序约定为：计算目标地址 → 读取旧值 → 计算右侧 → 相加并按目标类型处理 → 存回。
- `x += y;` 是语句，没有表达式值；`f(x += y)`、`return x += y;`、`x += y += z;` 都不属于本方案的合法语法。
- 当前前端不执行写回，也不新增未初始化变量的确定赋值分析。测试应先初始化目标，避免把运行时未定义值当成此扩展本身的问题。

## 3. 词法代码

`TokenType` 枚举增加：

```java
PlusAssign("PLUSEQ"),
```

仅添加本方案时，在 `Lexer.readOp()` 的 `switch (c)` 中增加：

```java
case '+' -> {
    int next = reader.read();
    if (next == '=') {
        addToken(TokenType.PlusAssign, "+=", start);
    } else {
        reader.unread(next);
        addToken(TokenType.Plus, "+", start);
    }
}
```

如果已经实现了 `++`，则合并成下面这**一个**分支；前提是枚举中同时存在 `Inc` 和 `PlusAssign`：

```java
case '+' -> {
    int next = reader.read();
    if (next == '+') {
        addToken(TokenType.Inc, "++", start);
    } else if (next == '=') {
        addToken(TokenType.PlusAssign, "+=", start);
    } else {
        reader.unread(next);
        addToken(TokenType.Plus, "+", start);
    }
}
```

两个版本二选一，不能添加重复 `case '+'`。`+ =` 是两个 token，不等于 `+=`；中间的注释也不能被词法扫描当作字符拼接。

## 4. AST 与解析代码

### 4.1 新增完整 AST 类

```java
package frontend.ast.statement;

import frontend.ast.expression.Exp;
import frontend.ast.expression.LVal;
import frontend.token.Token;

public class CompoundAssignStmt extends Stmt {
    private final LVal target;
    private final Token op;
    private final Exp value;

    public CompoundAssignStmt(LVal target, Token op, Exp value) {
        this.target = target;
        this.op = op;
        this.value = value;
    }

    public LVal getTarget() {
        return target;
    }

    public Token getOp() {
        return op;
    }

    public Exp getValue() {
        return value;
    }
}
```

继承 `Stmt` 已能输出 `<Stmt>`，不覆盖 `getName()`，也不额外输出 `<CompoundAssignStmt>`。

### 4.2 完整替换 `isAssignStmt()`

```java
private boolean isAssignStmt() {
    if (!among(TokenType.Ident)) {
        return false;
    }
    trace.save();
    boolean assign = false;
    try {
        parseLVal();
        assign = among(TokenType.Assign, TokenType.PlusAssign);
    } catch (RuntimeException e) {
        assign = false;
    } finally {
        trace.restore();
    }
    return assign;
}
```

不能只看标识符后的第一个 token，因为 `a[f(1)] += x;` 的赋值操作符在完整下标之后。现有 `trace` 同时回滚 token 位置、语法观察输出和错误，必须保留 `finally` 恢复，避免试探产生重复标签或错误条目。

### 4.3 替换 `parseStmt()` 中原赋值分支

```java
if (isAssignStmt()) {
    LVal lval = parseLVal();
    Token op = consumeAny(TokenType.Assign, TokenType.PlusAssign);
    Exp exp = parseExp();
    consume(TokenType.Semicolon);
    if (op.is(TokenType.PlusAssign)) {
        return watch(new CompoundAssignStmt(lval, op, exp));
    }
    return watch(new AssignStmt(lval, exp));
}
```

其它语句分派和末尾普通表达式语句保留，导入新增 AST 类。`atExpressionStart()` 不加 `PlusAssign`；`+=` 不能作为表达式起始符。

`x += 1;` 的左侧仍应输出 `<LVal>`，右侧正常输出 `<Exp>`，最后只输出一次 `<Stmt>`。试探过程中产生的轨迹不得泄漏。

## 5. 完整语义分析方法

在 `Traverser.visitStmt()` 中，与 `AssignStmt` 分支并列增加以下分支，并引入新类的 import：

```java
} else if (stmt instanceof CompoundAssignStmt compound) {
    analyzeCompoundAssign(compound);
```

新增方法：

```java
private void analyzeCompoundAssign(CompoundAssignStmt stmt) {
    LVal target = stmt.getTarget();
    Type left = analyzeLVal(target, false);
    SymbolVariable symbol = target == null ? null : target.getSymbol();
    if (symbol != null && symbol.isConst()) {
        errors.add(ErrorType.AssignToConstant, target.getIdent().location());
    }

    Type right = analyzeExp(stmt.getValue());
    if (left != null && right != null
            && (!left.isBasic() || !left.equals(right))) {
        errors.add(ErrorType.MismatchedParameterType, stmt.getOp().location());
    }
}
```

左值分析会处理未定义名称、数组下标及符号绑定。即使发现常量目标，仍分析右侧，以保留其它行上独立的语义错误。错误定位约定：`c/h` 在目标标识符，复合运算类型错误 `e` 在 `+=`。

这里借用现有 `e` 表示类型错误，与当前赋值 / 算术语义保持一致。整个数组即使两侧都是相同数组类型也必须拒绝，因为检查包含 `left.isBasic()`。

## 6. 为什么不能直接改写成两份左值

不能在 AST 层机械复制为 `a[f()] = a[f()] + rhs;`：这会在未来执行时调用两次 `f()`。保留 `CompoundAssignStmt`，后端可按下列步骤降低：

```text
address = evaluateAddress(target)  // 包含一次下标求值
oldValue = load(address)
rightValue = evaluate(value)
newValue = addWithTargetType(oldValue, rightValue)
store(address, newValue)
```

上面是后端设计伪代码，不是当前工程中已存在的 API。还应测试右侧修改了同一变量时是否遵守本文明确的“先读旧值”顺序。前端仅检查 AST / 类型，不能通过 `symbol.txt` 证明求值次数正确。

## 7. 完整样例与阶段预期

```c
int main() {
    int x = 1;
    int a[2] = {3, 4};
    char c = 'a';
    x += 2;
    a[0] += x;
    c += (char)1;
    printf("%d %d %c", x, a[0], c);
    return 0;
}
```

实施后 `error.txt` 为空；`lexer.txt` 含三条 `PLUSEQ +=`；`parser.txt` 的三条复合赋值各结束于 `<Stmt>`，不出现新的表达式层。`symbol.txt` 应为：

```text
2 x Int
2 a IntArray
2 c Char
```

未来运行预期 `3 6 b`；当前前端不执行该程序。

独立常量修改用例：

```c
const int k = 1;
int main() {
    k += 2;
    return 0;
}
```

预期 `error.txt` 为 `3 h`。将目标改为未定义的 `u`，独立预期为 `3 c`。

## 8. 边界测试

| 场景 | 预期 / 核查点 |
| --- | --- |
| `x += 0;`、`x += -1;`、`x += (x + 1);` | 普通、负值、引用目标；不改变右侧表达式优先级 |
| `a[f()] += g();` | AST 中一个目标下标；未来 `f` 只调用一次 |
| `x += changeX();` | 未来先读旧 x，再执行右侧；函数预先定义并返回 int |
| `char c = (char)255; c += (char)1;` | char 写回为 0 |
| `int x = 2147483647; x += 1;` | int 写回为最小 int |
| `c += 1;`、`x += (char)1;`、`arr += arr;` | 分别为严格类型 / 非标量错误 `e` |
| 常量标量、常量数组元素作为目标 | `h`；不能只检查变量名而漏掉数组元素 |
| `a[(char)0] += 1;` | 数组下标类型错误 `e` |
| `a[0 += 1;` | 现有 `k` 恢复，试探产生的错误先回滚，正式解析只保留一次 |
| 缺尾分号且换行后有合法语句 | `i` 在上一 token 行，后续语句仍可分析 |
| `1 += x;`、`f() += x;`、`(x) += 1;` | 目标不符合 `LVal`，解析拒绝；不伪造统一语法错误码 |
| `x += ;`、`x + = 1;`、`x += y += 1;` | 缺操作数 / token 分离 / 非法链式赋值，能终止并拒绝 |
| 多层下标表达式与大量连续复合赋值语句 | 回溯状态、输出数量及性能；基础 LVal 仍仅一维 |

验证单次下标求值时，可使用全局 `calls`，让 `index()` 中执行 `calls = calls + 1; return 0;`，再执行 `a[index()] += 2;`，观察最终 `calls` 为 1。这个例子不依赖 `++`，适合单独测试本扩展；运行断言需等后端实现。

## 9. 测试生成器适配

新增规则文件写 `Stmt -> LVal '+=' Exp ';'`，token 配置写 `{"+=":"PLUSEQ"}`。默认合并规则即可，不能用只含该候选式的 `--replace` 删除其余所有 `Stmt` 形式。先用语法片段模式检查推导；用于完整程序时，在 `testgen/oracle.py` 的 `SemanticModel.statement()` 中显式识别 `+=`：

1. 检查完整的 `LVal '+=' Exp ';'` 形状，而非只看到首个子节点为 `LVal` 就把它当成普通 `=`。
2. 验证可修改标量、两侧同类型及下标类型，保留名称绑定和常量目标规则。
3. 为语义合法集与错误集分别建立独立预期；复合赋值不改变符号声明和作用域。
4. 定向添加表中的合法、`c/e/h/i/k` 及非法语法样例；单独验证 `+=` 出现在实际终结符覆盖统计中。

不能仅配置一个二元表达式的 `"same"` 契约，因为本方案是修改目标的语句。当前生成器中相似的普通赋值处理也不能替代对新操作符形状的显式确认。基础随机样例的外层包装和类型筛选不保证覆盖常量修改、缺操作数与单次求值等边界。
