# 文法扩展方案：按位取反 `~`

状态：修改建议，尚未实施。本文展示如何复用已有 `UnaryOp` / `UnaryExp`，不增加新的 AST 种类。返回[示例目录](README.md)。

## 1. 规则与语义

保留已有候选式，只向 `UnaryOp` 增加 `~`：

```text
UnaryOp -> '+' | '-' | '!' | '~'
UnaryExp -> PrimaryExp | Ident '(' [FuncRParams] ')' | UnaryOp UnaryExp | '(' BType ')' UnaryExp
```

约定：

- 优先级和已有前置单目运算一致，通过递归处理，例如 `~x * y` 等于 `(~x) * y`。
- 操作数允许 `int`、`char` 基本类型值，结果沿用操作数类型。`int` 按 32 位逐位取反，`char` 取反后 `& 0xFF`。
- 没有副作用，可用于常量表达式；`const int k = ~0;` 的值为 `-1`。
- 不能对整个数组或 `void` 调用结果取反；未定义名称仍报 `c`，类型不匹配仍报 `e`。
- 为沿用当前项目“相邻相同普通单目运算符非法”的检查，本方案将 `~~x` 判为 `e`。`~(~x)` 合法，因为括号引入了主表达式层。这是本方案的规则选择，并非其它语言的通用规则。
- `~` 不受已有 `!` 的“只能位于条件上下文”约束影响；`!` 的原限制继续保留。

## 3. 词法与语法修改代码

### 3.1 token 与符号表

在 `TokenType` 枚举中增加：

```java
Tilde("BITNOT"),
```

在 `Symbols.TABLE` 的初始化列表增加一项，沿用该文件的现有写法：

```java
Map.entry('~', TokenType.Tilde)
```

`BITNOT` 是本文选定的扩展输出名。新增 map 项时检查逗号及是否需要扩充现有容器，不能影响字符串、字符常量和注释的扫描。

### 3.2 `Parser` 的表达式入口

替换 `atExpressionStart()` 为：

```java
private boolean atExpressionStart() {
    return among(TokenType.Plus, TokenType.Minus, TokenType.Not, TokenType.Tilde,
            TokenType.LParen, TokenType.Ident, TokenType.IntConst, TokenType.CharConst);
}
```

它同时影响 `return` 的可选表达式、函数调用的首个实参和部分数组长度入口。只改 `parseUnaryExp()` 会造成 `return ~x;`、`f(~x)` 仍无法正常解析。

将 `parseUnaryExp()` 开头的普通单目分支改为以下代码，其余类型转换、调用、主表达式分支保留：

```java
if (among(TokenType.Plus, TokenType.Minus, TokenType.Not, TokenType.Tilde)) {
    UnaryOp op = watch(new UnaryOp(consumeAny(
            TokenType.Plus, TokenType.Minus, TokenType.Not, TokenType.Tilde)));
    return watch(UnaryExp.unary(op, parseUnaryExp()));
}
```

`~x` 的局部语法轨迹应在操作数之前输出 `BITNOT ~`、`<UnaryOp>`，随后输出操作数及外层 `<UnaryExp>`，不能发明 `<BitNotExp>` 标签。

## 4. 语义检查：复用现有方法

`UnaryExp.Kind` 不变，`analyzeUnaryExp()` 已将普通单目运算转交 `analyzeUnaryOp()`。当前方法已经满足本文的取反类型规则，可保持原实现。其完整逻辑如下，便于与其它扩展合并时核查：

```java
private Type analyzeUnaryOp(UnaryExp exp, boolean constContext) {
    Type operand = analyzeUnaryExp(exp.getOperand(), constContext);
    if (exp.getOp() != null
            && exp.getOp().getToken().is(TokenType.Not)
            && !insideCondition) {
        errors.add(ErrorType.MismatchedParameterType,
                exp.getOp().getToken().location());
    }
    checkConsecutiveUnary(exp, operand);
    if (operand != null && !operand.isBasic()) {
        errors.add(ErrorType.MismatchedParameterType,
                exp.getOp().getToken().location());
        return null;
    }
    return exp.getOp().getToken().is(TokenType.Not) ? Type.Int : operand;
}
```

`checkConsecutiveUnary()` 已比较外层与内层运算符的 token 类型，新增 `Tilde` 后自然会拒绝 `~~x`。若希望以后放开该形式，应明确修改契约、此检查及测试生成器，不能只删掉某一条用例。

通过原有 `put()` 设置 `UnaryExp.charResult`，才能让字符常量求值保留当前工程的截断规则；不要另写忽略类型结果的取反 AST 节点。

## 5. 常量求值

在 `UnaryExp.calculateUnary()` 的 `switch` 中增加 `Tilde` 分支。建议的方法完整形式：

```java
private int calculateUnary() {
    int value = operand.calculateConst();
    return switch (op.getToken().getType()) {
        case Plus -> value;
        case Minus -> -value;
        case Tilde -> ~value;
        case Not -> throw new UnsupportedOperationException(
                "常量表达式中不能出现逻辑非");
        default -> throw new UnsupportedOperationException(
                "不支持的单目运算符: " + op.getToken().getType());
    };
}
```

外层 `calculateConst()` 已根据 `charResult` 对最终结果做 `& 0xFF`。例如 `~(char)0` 的类型为 `char`，值为 `255`；`~0` 的类型为 `int`，值为 `-1`。计算顺序应是先分析绑定符号并标记类型，再进行常量折叠。

## 6. 完整样例与阶段预期

实施扩展后，应接受：

```c
const int k = ~0;
int f(int x) {
    return ~x;
}
int main() {
    char c = ~(char)0;
    int x = f(~k);
    printf("%d %d", x, (int)c);
    return 0;
}
```

- `lexer.txt`：每个 `~` 对应一条 `BITNOT ~`。
- `parser.txt`：使用原有 `<UnaryOp>` / `<UnaryExp>`；不新增表达式标签。
- `error.txt`：空。
- `symbol.txt`：应为以下内容，沿用当前作用域编号和不输出 `main` 的约定。

```text
1 k ConstInt
1 f IntFunc
2 x Int
3 c Char
3 x Int
```

用于未来后端的运行预期是 `-1 255`。当前前端并不执行该程序。

独立反例：

```c
int main() {
    int x = 1;
    x = ~~x;
    return 0;
}
```

建议预期 `error.txt` 为 `3 e`，错误定位在外层 `~`。删除一个 `~` 后应恢复合法。

## 7. 边界与回归

| 用例 | 应检查的结果 |
| --- | --- |
| `~0`、`~(-1)`、`~2147483647`、`~(-2147483647 - 1)` | 分别为 `-1`、`0`、最小 int、最大 int |
| `~(char)0`、`~(char)255`、`(int)~(char)0` | 字符截断为 `255` / `0`，显式转换后为 int |
| `~~x` / `~(~x)` | 前者 `e`，后者合法；验证相邻限制确实按 AST 检查 |
| `~-x`、`-~x`、`~x * y + z` | 混合单目与乘加优先级 |
| `return ~x;`、`f(~x)`、`int a[~(-4)];` | 起始集合及常量数组长度，最后一个长度为 3 |
| `~arr`、`~voidFunc()`、`~unknown` | 非基本类型 `e`；未定义名称 `c`，函数必须预先声明 |
| `~/* comment */x`、字符串中的 `"~"`、源码末尾单个 `~` | 注释跳过、字符串不拆分、缺操作数能终止并拒绝 |
| 多层 `~(~(...))` | 递归深度与语法输出数量；从小深度逐步增大 |

同一错误行还存在其它错误时，以当前 `ErrorTable` 的优先级为准；不要把独立反例的期望直接用于混合错误程序。

## 8. 与测试生成器配合

可把 `{"~":"BITNOT"}` 保存到新配置文件，通过 `--tokens` 指定；规则只需输入 `UnaryOp -> '~'`，默认会与已有候选式合并。纯语法模式可先生成片段，检查 token 和推导结构：

```powershell
python -m testgen --mode syntax --rule "UnaryOp -> '~'" --focus UnaryOp --alternative 4 --tokens build/bitnot-tokens.json --count 5 --out build/bitnot-fragments
```

先自行创建上述 JSON 文件；第 4 个候选式以当前基础 `UnaryOp` 只有 `+/-/!` 为前提。这批输入是单个运算符片段，应交给对应语法入口，不能作为完整程序运行。

完整程序的可靠预期还需在 `testgen/oracle.py` 的单目语义处理中显式支持 `~`，保留相邻同类型单目检查及 `char` 类型规则。需要检测取反值、字符截断、数组长度时，另补常量值验证和定向用例，不能仅用“类型透明”配置冒充完整支持。基础随机生成不会自动穷举上述边界。
