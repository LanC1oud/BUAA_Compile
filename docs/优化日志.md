# 优化日志

本文按轮次记录优化动机、实现代码、语义约束和验证结果。所有数字均来自课程版 MARS 的实际指令统计；加权周期不等同于宿主机耗时。

## 使用方式与代码入口

- 默认开启优化，`Compiler --no-optimize` 保留原始生成路径。
- `src/utils/Configure.java` 管理优化开关和 Pass 列表，`Controller`、界面 `Pipeline` 使用相同后端入口。
- `src/mips/MipsGenerator.java` 负责指令选择、寻址、栈帧与调用约定。
- `src/mips/MipsConstants.java` 分析纯整数常量，保留每一步 i8 回绕，不传播可变内存。
- `src/mips/MipsFunctionPlan.java` 在生成前分析可融合比较、跨块结果和块内末次使用。
- `src/mips/MipsLocalRegisters.java` 管理 `$t3～$t8`、脏值、驱逐与按需写回。
- `src/mips/pass/RemoveRedundantJumps.java` 删除跳到下一标签的 `j/nop`。
- `tests/run-mips-tests.py` 检查优化开关与延迟槽开关的四种组合，比较完整输出、运行异常并保存指令统计。

每轮先保存源码快照与上一轮统计，完成正确性验证后再比较相同用例的开销。收益只适用于所列测试集合。

### 阅读约定

本文中的方法名对应当前源码。第一轮引入的方法有些在第二轮继续扩展，因此每节会分别说明历史行为和当前行为；历史实现可以从对应快照还原。
下面的 IR、汇编和伪代码用于说明转换规则，省略了无关标签、参数搬运和部分类型信息，不是某个测试文件的完整逐字输出。

“源程序局部变量”和“IR 临时结果”是两类存储。前者通常对应 `alloca` 对象，程序可能通过数组形参访问它；后者是后端为了保存某条指令的结果而使用的内部值槽。
本轮复用的是内部值槽，不把真实数组、局部对象或调用传参区混在其中。

### 当前代码的调用顺序

编译入口位于 [Compiler.java](../src/Compiler.java)、[Controller.java](../src/utils/Controller.java) 和界面的 [Pipeline.java](../ui/compilerui/pipeline/Pipeline.java)。
`Compiler` 解析 `--optimize`、`--no-optimize`，更新 `Configure.optimize`；Controller 按开关选择不同生成器，UI Pipeline 按 `CompilerSettings.optimize()` 作相同选择。

```text
IrGenerator.generate() 产生 IrModule
  → 关闭优化：new MipsGenerator().generate(module)
      → 分配标签，输出数据段和启动入口
      → 构建基础 MipsFrame，逐条降低 IR，输出共同返回出口
  → 开启优化：new OptimizedMipsGenerator(Configure.mipsPasses).generate(module)
      → 复用基础生成流程，在 pass/ 内覆盖需要优化的步骤
          → MipsConstants：识别可重算常量
          → MipsFunctionPlan：分析融合、跨块使用和末次使用
          → MipsFrameOptimization：分配对象与可复用回退槽
          → MipsLocalRegisters：管理块内寄存器和按需写回
          → OptimizedMipsGenerator：直接优化指令、地址与值加载/保存
      → 执行 MipsPass 列表
  → MipsPrinter 输出文本
```

`MipsGenerator` 不包含优化开关、优化器调用或 Pass 调度，也不依赖 `mips.pass`。`OptimizedMipsGenerator` 继承基础生成器，直接管理生成期间的优化状态和指令选择，调用继承的基础发射方法；依赖方向为优化层到基础层。
除 `RemoveRedundantJumps` 是汇编生成后的 Pass 外，本文多数优化发生在降低期间，不改写输入 IR。
`--ir-before` 输出的是 IR Pass 执行前的 LLVM 文本，不是优化前 MIPS。

原来的 `MipsGenerator(boolean, List<MipsPass>)` 和 `MipsGenerator(List<MipsPass>)` 构造器已移除，调用方改为在入口选择基础或优化生成器。下文各轮记录保留当时的算法说明与历史方法名；当前类职责以 [MIPS 后端设计](MIPS后端设计.md) 为准。

此次入口分离以重构前后 42 个用例、四种配置的汇编逐字节对照验证，覆盖无用形参、额外传参、数组、递归、大偏移、窄整数和寄存器压力；生成器重用及输入 IR 不变性检查通过。

入口分离后进一步合并了优化生成器与原 `MipsGenerationOptimization`，并删除仅用于两者转发的 `MipsEmission` 接口和内部适配器。常量分析、使用关系分析、栈帧优化和块内寄存器管理保持独立。相同 42 个用例、四种配置的汇编与合并前逐字节一致，直接 IR 模型及 UI 管线回归通过。

### 1.1 纯整数常量分析与使用处重算

**代码位置：**[MipsConstants.java](../src/mips/MipsConstants.java) 的构造器、`evaluate()`、`get()`，以及 [MipsGenerator.java](../src/mips/MipsGenerator.java) 的 `emitInstruction()`、`load()`。

`MipsConstants` 使用 `IdentityHashMap<Value, Constant> values` 保存“某个 IR 对象已经计算出的常量”。键是 IR 对象身份，不是可能在不同函数中重复的 `%v0` 之类名字。
构造器按函数的基本块、指令顺序扫描；`get(value)` 遇到原生 `Constant` 就直接返回，否则查询 `values`。

`evaluate()` 先要求结果是整数类型，再检查所需操作数是否均已知。支持加减乘、有符号和无符号除余、整数比较、ZEXT/TRUNC。
有符号窄整数先经 `signed()` 按原位宽符号扩展；无符号除余使用 Java 的 `Integer.divideUnsigned()`、`remainderUnsigned()`。
除数为零，或有符号除法发生最小值除以 -1 的溢出时，分析返回 `null`，不把这个运算折成普通常量。

每得到一步结果，都调用 `Constant.integer(resultType, result)`。
该工厂在 [Constant.java](../src/llvm/value/Constant.java) 中将 i8 截断为 `value & 255`，i1 截断为 `value & 1`，因此不会把 char 的多步运算错误地当成最后才截断的 int 运算。

```llvm
; 规则示意：每一步按 i8 规范化
%a = add i8 255, 1        ; 已知结果 0
%b = udiv i8 %a, 2        ; 已知结果 0
%c = zext i8 %b to i32    ; 已知结果 0
```

生成汇编时，`emitInstruction()` 遇到分析结果非空会跳过该指令；以后 `load(%c, "$a0")` 查询到常量，只需装入 0。
原来的 `Instruction` 没有删除、替换，也没有改动它的使用链。这也是优化前后 LLVM 文本保持一致的原因。

LOAD、函数返回值和可变内存内容不会因“看起来没有变化”而被推断为常量。
分析也是按登记顺序的一次扫描，不是对整个 CFG 做迭代的条件常量传播。

### 1.2 常量条件直接选择跳转目标

**代码位置：**`MipsGenerator.emitInstruction()` 的 `BR` 分支。

对三操作数条件分支，后端先查询 `constants.get(condition)`。已知为非零就选择真目标，已知为零就选择假目标，生成一条 `j` 及其空延迟槽。
这一判断优先于后续比较分支融合，避免继续为已知条件生成比较和布尔值读取。

```llvm
br i1 1, label %yes, label %no
```

对应规则是直接跳到 `%yes`。第二轮还会在跳转前执行 `spillLiveOut()`，确保目标块需要的结果已经保存。
这里仅简化跳转，尚未从模块中删除不可达基本块；此前的有副作用调用也不会被删除。

### 1.3 固定栈地址折叠成直接访存

**代码位置：**`MipsGenerator.stackAddress()`，以及 `emitInstruction()` 的 LOAD、STORE、GEP 分支。

`Frame.objects` 记录每个实际局部对象相对当前 `$sp` 的偏移。
`stackAddress(value)` 首先查这个表；如果值是 GEP，就递归求基址，并要求所有下标都能由 `MipsConstants` 得到常量，再按被索引类型的大小累加字节偏移。
它返回具体偏移，返回 `null` 表示不能证明是固定栈地址。

假设局部 `int a[4]` 位于 `$sp + 16`，则 `a[2]` 的偏移是 `16 + 2*4 = 24`。

```mips
# 原始规则的核心：先计算地址，再访问
addiu $t0, $sp, 16
li    $t1, 2
sll   $t1, $t1, 2
addu  $t0, $t0, $t1
lw    $t1, 0($t0)

# 固定偏移可证明后的核心
lw    $t1, 24($sp)
```

LOAD/STORE 根据这个偏移直接调用 `memory()`；字对象选择 `lw/sw`，字节对象选择 `lbu/sb`。
固定栈地址 GEP 本身不再输出计算指令；当地址被当作实参传递时，`load()` 会重新构造 `$sp + offset`，仍得到正确指针。

`stackAddress()` 不把数组形参或全局地址误认为本函数栈对象。数组形参的真实地址由运行时决定，不能用本函数的对象偏移代替。
第二轮的 `MipsFunctionPlan.isStackAddress()` 只判断“是否可重算”，用于提前省槽；这里的 `stackAddress()` 才计算真实数值偏移，两者职责不同。

### 1.4 普通 GEP 合并常量偏移并跳过零下标

**代码位置：**`MipsGenerator.gep()`。

当基址不是可直接折叠的局部栈地址时，仍需要输出 GEP。方法先把基址装入 `$t0`，然后逐个处理下标：

1. 根据当前被索引类型调用 `sizeOf()` 得到步长；后续数组下标进入元素类型。
2. 常量下标只累加到 `constantOffset`，不立即输出乘法、移位和加法。
3. 动态下标装入 `$t1`。步长 4 使用 `sll ...,2`；步长 1 不做缩放；其他步长使用乘法。
4. 所有常量偏移在末尾合并成一次 `addOffset()`；总偏移为零则省略。

LLVM 数组 GEP 常见的首个下标 0 因而完全不需要运行时指令。
全局 `int a[4]` 的 `a[2]` 可以简化为装入全局地址后加 8；动态 `char[]` 下标则只需要地址加法。

### 1.5 缓存寄存器中已有的不可变 IR 值

**代码位置：**`MipsGenerator.registers`、`sameValue()`、`load()` 和 `emit()`。

第一轮增加 `LinkedHashMap<String, Value> registers`，记录某个物理寄存器当前包含哪个 IR 值。
同一个 IR 对象可以复用；两个常量则要求类型与数值都相同。变量名相同、内存地址相同，都不构成复用条件。

第一轮的 `save()` 仍通常写栈，但会同时记录计算寄存器中的值。紧随其后的 `load()` 如果发现目标寄存器已包含该值，可以不输出指令；在另一寄存器中则用 `move` 替代 `lw`。

缓存的失效由统一的 `emit()` 维护：

- 操作码在 `REGISTER_WRITERS` 中时，取出目标寄存器，删除该寄存器的旧记录。
- 遇到 `jal` 或 `syscall`，清空整个缓存。
- 进入新函数、新基本块时，也清空缓存。

例如，对同一个 LOAD 结果的两次使用可以复用寄存器，但源程序同一变量的两次 LOAD 是两个不同的 IR 对象。
即使数组经形参修改后再次读取同一地址，第二次 LOAD 也不会被替换成第一次读取的旧值。
第二轮保留这层缓存，并在它与回退槽之间加入独立的块内寄存器分配器，详见第 2 轮。

### 1.6 用有范围保证的立即数指令实现加减

**代码位置：**`MipsGenerator.selectArithmetic()`、`shortImmediate()`。

该方法在通用 `arithmetic()` 之前尝试选择较短的指令。ADD、MUL 可交换左右操作数以把常量放到右侧；SUB 和除法不会交换。
`x + c` 在 `c` 位于 -32768～32767 时选择 `addiu`；`x - c` 仅在 `-c` 位于该范围时选择 `addiu`。
超出范围就返回通用生成路径，而不是把大立即数直接塞进指令。

```mips
# x + 3 的核心变化
li   $t1, 3                # 原先先装入第二个操作数
addu $t2, $t0, $t1

addiu $t2, $t0, 3         # 优化后的核心
```

加减使用不触发有符号溢出异常的 `addu/subu/addiu`，保留低 32 位；char 结果再由 `save()` 按 8 位规范化。

### 1.7 常量乘法改为零、取负或移位

**代码位置：**`selectArithmetic()` 的 MUL 分支。

识别条件是常量为 0、-1，或 `Integer.bitCount(number) == 1`。
乘 0 输出常量 0；乘 -1 用 `subu $t2,$zero,$t0`；乘 2 的幂用 `Integer.numberOfTrailingZeros()` 确定左移位数。
这也涵盖 32 位数 `0x80000000`：虽然按有符号解释是 INT_MIN，但乘法只保留低 32 位，可以用左移 31 位实现。

```mips
mult $t0, $t1             # 原先 x * 8 的乘法核心
mflo $t2

sll  $t2, $t0, 3         # 常量 8 的实现
```

`x * 3` 等未匹配情况仍走通用乘法。对于 i8，移位或取负后仍调用 `save()` 截断，不能省略逐步回绕。
该优化不会删除前面已经生成的函数调用，也没有实现一般性的死表达式删除。

### 1.8 无符号 2 的幂除余改为右移和掩码

**代码位置：**`selectArithmetic()` 的 UDIV/UREM 分支、`mask()`。

当非零除数 `d` 只有一个置位比特时，`x / d` 使用逻辑右移，`x % d` 使用 `x & (d-1)`。
这里必须使用 `srl`，不能对高位为 1 的无符号值使用算术右移。

`mask()` 在掩码为 0～65535 时使用 `andi`；掩码更大时用 `li` 装入寄存器，再执行 `and`。
因此 32 位无符号除数 `0x80000000` 的余数掩码 `0x7fffffff` 也不会因 16 位立即数字段而被截断。
char 运行时值已经保持 0～255，除以 `(char)2` 等情况沿用同一无符号规则。

### 1.9 有符号 2 的幂除余保持向零截断

**代码位置：**`selectArithmetic()` 的 SDIV/SREM 分支、`MipsConstants.signed()`、`signExtend()`。

有符号负数直接算术右移通常是向负无穷取整，不能代替向零截断的除法。
后端先按操作数位宽解释常量除数，并将窄整数被除数符号扩展，再对绝对值为 2 的幂的除数使用以下规则：

```text
m = abs(d) = 2^k
bias = (x >> 31) & (m - 1)
q_positive = (x + bias) >> k

SDIV：d > 0 时 q = q_positive；d < 0 时 q = -q_positive
SREM：r = x - (q_positive << k)
```

余数只需要绝对值为正的除数所对应的商。余数符号随被除数，不因除数为负而另行取负。
例如 `-7/4 = -1`、`-7/-4 = 1`，两种除数下的余数均为 -3。

以除以 4 为例，关键汇编为：

```mips
sra  $t1, $t0, 31
andi $t1, $t1, 3
addu $t2, $t0, $t1
sra  $t2, $t2, 2
# 如果除数是 -4，SDIV 再对 $t2 取负
# 如果求余，则左移还原 q_positive*4，再用原 $t0 减去它
```

除数为 ±1 单独处理；除数为 0、INT_MIN 或绝对值不是 2 的幂时不走这条选择路径。
针对 i8 的有符号 IR 运算，最终结果仍通过 `save()` 转成相应位模式。

### 1.10 无用结果省写栈与叶子函数省返回地址访存

**代码位置：**`save()` 开头的使用者检查，以及 `Frame.needsReturnAddress`、`emitFunction()`。

`save()` 在优化开启且 `value.getUses().isEmpty()` 时直接返回，不生成结果规范化、保存动作。
这只说明“不保存无人使用的结果”，不等价于删除了整个运算。
特别是 CALL 仍先执行普通调用或 syscall，然后才决定返回值是否需要保存；输入输出等副作用必须保留。

构建 Frame 时扫描所有 CALL，只有被调用者不是外部函数才令 `needsReturnAddress = true`。
普通调用生成 `jal`，会改变 `$ra`，需要入口保存、尾声恢复。六个外部 I/O 接口转换为 syscall，不属于这种普通函数调用。
第一轮只省略叶子函数的 `$ra` 访存，仍保留原布局中的空间；第二轮才连返回地址槽和空栈帧调整一起省略。

### 1.11 删除直接跳到下一标签的跳转

**代码位置：**[RemoveRedundantJumps.java](../src/mips/pass/RemoveRedundantJumps.java) 的 `run()`。

Pass 顺序扫描 `MipsModule.getText()`，只在三个连续文本行分别为 `j target`、`nop`、`target:` 时，删除前两行。
标签保留，其他指令照常复制到新列表，再通过 `replaceText()` 替换文本段。

```mips
j end
nop
end:
# 上面可以直接顺序执行到 end，因此删除 j 与对应 nop
```

这是精确的相邻模式，不是任意跳转线程化，也不删除条件分支。
由于被删跳转的延迟槽本来就是 nop，删除后在延迟槽开启与关闭时均保持行为。

## 第 2 轮 栈帧压缩与块内寄存器分配

日期：2026-11-23。状态：已完成。

### 2.1 函数分析先于栈帧和指令生成

**代码位置：**`MipsGenerator.emitFunction()`。

第二轮将函数准备顺序调整为先创建 `MipsConstants`，再创建 `MipsFunctionPlan`，然后构建 `Frame(function, plan)`。
如果先按全部 IR 结果分配空间，再在输出汇编时删除常量或比较，栈帧仍然会包含它们，所以“省槽”必须依赖生成前的分析结果。

之后创建 `MipsLocalRegisters`，并传入一个真正写栈的回调：

```
locals = new MipsLocalRegisters(plan,
        (value, register) -> memory("sw", register, frame.slots.get(value), "$sp"));
```

分配器负责判断什么时候要写回；生成器负责根据已经确定的槽偏移输出 `sw`，包括超出 16 位偏移时的地址合成。
这种分工使局部分配器不必了解栈帧的字节布局。

`currentBlock` 在保存入口形参时为 `null`，所以形参先写入自己的槽。
进入基本块后才设置 `currentBlock`，调用 `locals.begin(block)` 并按原始 IR 下标更新 `position`。
分析和生成使用同一套原始指令下标，即使某条指令被融合、没有输出汇编，其位置也不会从分析中错位。

### 2.2 记录末次使用与跨块结果

**代码位置：**[MipsFunctionPlan.java](../src/mips/MipsFunctionPlan.java) 的构造器、`lastUse()`、`crossesBlock()`、`liveAfter()`。

核心数据结构如下：

| 字段 | 保存的含义 | 使用位置 |
| --- | --- | --- |
| `crossBlock` | 指令结果是否被定义块以外的块使用 | 决定独立槽、块出口保存和保守存活 |
| `lastUses[block][value]` | 值在该块中最后一个消费者的原始指令下标 | 释放寄存器、复用槽、调用前保存 |
| `stackAddresses` | 值是否是可重算的局部栈地址 | `needsSlot()` 提前排除地址槽 |
| `fused` | 已归入融合链、无需单独输出的指令 | 生成时跳过，布局时省槽 |
| `branches` | 分支对应的实际比较及逻辑反向标记 | 分支生成和使用位置重定位 |

分析首先识别比较融合链，并检查每个指令结果的 `getUses()`。
只要存在 `use.user().getParent() != definingBlock`，就将该结果加入 `crossBlock`。
这是一种保守的跨块使用标记，并没有计算精确 CFG 活跃变量集合或支配树。

随后为每个基本块建立末次使用表。顺序扫描指令，遇到操作数便用当前下标覆盖其记录，最后留下最大下标。
对于融合链，跳过链内指令，改为在真正的 BR 位置记录最底层比较的操作数。

```text
原始位置 7：%cmp = icmp ... %x, %y
原始位置 8：%z   = zext %cmp
原始位置 9：%c   = icmp ne %z, 0
原始位置 10：br %c, yes, no

融合后在位置 10 才读取 %x 和 %y：
lastUses[block][%x] = 10
lastUses[block][%y] = 10
```

如果仍把末次使用记在位置 7，分配器可能在真正生成分支前就释放这些值。
因此融合识别必须在末次使用统计之前完成。

当前存活判断可以写成：

```text
liveAfter(value, block, position) =
    crossesBlock(value) || lastUse(value, block) > position
```

跨块结果即使在当前块内已经没有后续使用，也会被保守保留或写回。
没有出现在某块的末次使用记录时返回 -1，不会把普通块内值误判为仍活跃。

### 2.3 先排除不需要的槽，再布局真实对象与持久结果

**代码位置：**`MipsFunctionPlan.needsSlot()`、`isStackAddress()`，以及 `MipsGenerator.Frame` 的优化分支。

`needsSlot(instruction)` 要求以下条件同时成立：

1. 结果不是 void，也不是 ALLOCA；ALLOCA 对象由 `objects` 单独管理。
2. IR 结果存在使用者。
3. `MipsConstants` 没有给出可重算常量。
4. 指令没有被归入比较融合链。
5. 结果不是可从局部对象重算出的固定栈地址。

满足这些条件表示“需要预留运行时回退位置”，不表示一定执行写栈。
即使值最终一直留在寄存器里，布局阶段仍为它提供一个可用的回退位置；实际是否写入由分配器决定。

优化布局从低地址到高地址依次处理：

1. 最大额外实参区，大小由本函数所有 CALL 中超过四个参数的最大数量决定。
2. 有 IR 使用者的形参值槽，每个 4 字节。
3. 有使用者的 ALLOCA 对象，按对象类型对齐并占用真实大小。
4. 需要槽且跨块使用的指令结果，每个保留独立 4 字节槽。
5. 块内临时结果的公共回退区域，按下一节的区间算法复用。
6. 仅在调用普通函数时分配的 `$ra` 槽，以及使总大小按 8 字节对齐的填充。

局部 char 对象可以只占 1 字节，但临时 char 的回退槽仍为 4 字节，因为这里保存的是已规范化的机器整数值。
真实局部对象保持独立区域，不能因为某次 LOAD 结果已经死亡就让另一临时值覆盖源变量或数组。
字节对象之后进入值槽区域时会重新按 4 字节对齐。

### 2.4 用使用区间复用块内回退槽

**代码位置：**`Frame.Interval`，以及 `Frame` 中的 `active`、`free`、`localBase`、`peak`。

每个块内结果的区间起点是定义位置，终点是 `plan.lastUse(value, block)`。
`active` 是按终点排序的优先队列，保存已分配但尚未结束的 `Interval(end, slot)`；`free` 是按槽编号排序的空闲队列。

按定义顺序处理需要槽的局部结果时：

```text
while active 非空且最早终点 <= 当前定义位置：
    将该区间的 slot 放回 free

slot = free 非空 ? 取最小空闲编号 : 新建编号 count++
slots[value] = localBase + slot * 4
将 Interval(lastUse(value), slot) 放入 active
```

终点使用 `<=` 而不是 `<` 是有意设计：当前指令先通过 `load()` 读取全部输入，完成计算后才 `save()` 输出。
因此可以在输入最后一次被读取的同一条指令上，把结果保存到已经结束的输入槽中。

| 值 | 定义位置 | 末次使用位置 | 可选槽编号 |
| --- | ---: | ---: | ---: |
| `%a` | 0 | 2 | 0 |
| `%b` | 1 | 2 | 1 |
| `%c = add %a, %b` | 2 | 5 | 0 |
| `%d` | 3 | 4 | 1 |
| `%e` | 4 | 5 | 1 |

这个示意中 `%c` 计算时先读取 `%a/%b`，再复用槽 0；最终只需两个局部槽。
CALL 的参数同样在返回结果保存之前已经读取并放到参数寄存器或额外实参区，所以结束于 CALL 的输入区间也能与该 CALL 的结果复用。

每个基本块独立运行上述算法，但都使用相同的 `localBase`。
函数只保留所有块所需槽数的最大值 `peak`，不是各块需求之和。
跨块结果已经在前面的独立区域分配，不会被下一个块的局部槽覆盖；函数每次调用仍有自己的栈帧。

栈帧变小后，第五个及之后形参的位置仍按“当前函数帧大小 F + 调用方额外参数偏移”读取，没有沿用优化前的固定 F。

### 2.5 用六个独立临时寄存器保存块内结果

**代码位置：**[MipsLocalRegisters.java](../src/mips/MipsLocalRegisters.java) 的 `POOL`、`assign()`、`remove()`、`writeBack()`。

寄存器职责固定如下，避免计算途中被分配器覆盖输入：

| 寄存器 | 职责 |
| --- | --- |
| `$t0～$t2` | 现有指令选择的操作数和结果工作寄存器 |
| `$t3～$t8` | 分配器使用的六个块内结果寄存器 |
| `$t9` | 大立即数和大偏移地址合成 |
| `$a0～$a3`、`$v0` | 调用参数和返回值，不作为块内结果池 |

管理器维护三个相互配合的数据结构：

- `contents[register] = value`：这个池寄存器当前存什么。
- `homes[value] = register`：某个值现在位于哪个池寄存器。
- `dirty`：值已在池中，但其回退槽还没有更新；这里的“脏”指后端值槽状态，不是源程序内存对象的别名分析。

`assign(value, position)` 首先释放 `liveAfter()` 为假的旧值。
释放已死值只删除映射和 dirty 标记，不需要保存它。
然后按固定 POOL 顺序取空闲寄存器，保证同一输入重复生成时选择稳定。

当六个寄存器都占用时，方法比较旧值在当前块中的末次使用位置，选择较远的值驱逐。
对仍需跨块保存、但当前块已没有后续使用的值，按 `Integer.MAX_VALUE` 处理。
这不是基于“下一次使用距离”的最优替换，而是基于已有末次使用信息的局部启发式。

驱逐前调用 `writeBack(old)`。只有 `dirty.remove(old)` 成功才触发写栈回调，已经更新过的槽无需重复写。
随后移除旧映射，建立新 `contents/homes`，并把新值标记为 dirty。
真正把工作寄存器中的计算结果搬到所选池寄存器，由生成器的 `save()` 执行。

### 2.6 load 与 save 如何接入新分配器

**代码位置：**`MipsGenerator.load()`、`save()`。

当前 `save(value, register)` 的执行顺序是：

1. 优化开启且没有使用者时返回。
2. i8 执行 `andi ...,255`，i1 执行 `andi ...,1`，先规范化，再保存。
3. 位于普通基本块内时调用 `locals.assign()`，得到 `$t3～$t8` 中的一个 home，用 `move` 保存结果。
4. 入口形参保存阶段 `currentBlock == null`，或关闭优化时，仍直接写入栈槽。
5. 更新第一轮的工作寄存器缓存。

因此，方法名仍叫 `save()`，但它在优化模式下已经不表示“无条件 sw”。

```mips
# 第一轮：结果通常立即写入回退槽
addu $t2, $t0, $t1
sw   $t2, result_slot($sp)

# 第二轮：结果先放在池寄存器中
addu $t2, $t0, $t1
move $t3, $t2
# 只有被驱逐、跨块使用或需要跨调用保留时，才可能 sw $t3
```

当前 `load()` 依次尝试：

1. 将已知常量作为查询键；检查目标工作寄存器是否已经有该值，若有则省略搬运。
2. 查询 `locals.get(value)`，若有 home，从池寄存器搬到目标寄存器。
3. 查询第一轮的其他工作寄存器缓存，尝试 `move`。
4. 常量用 `li`；固定局部地址从 `$sp` 重算；全局地址用 `la`。
5. 剩余值从 `frame.slots` 对应位置执行 `lw`。

先检查目标寄存器是为了避免一个值既在工作寄存器又在 home 中时，仍多输出一次 `move`。
池中的值被驱逐后，如果某个未被覆盖的工作寄存器仍有其副本，也允许继续复用；工作寄存器是否有效仍由统一 `emit()` 维护。

### 2.7 调用前保存顺序及块出口保存

**代码位置：**`MipsGenerator.call()`、BR 分支，以及 `MipsLocalRegisters.beforeCall()`、`spillLiveOut()`。

普通调用和 syscall 都走以下顺序：

1. 先通过 `load()` 读取所有实际参数，放入 `$a0～$a3` 或当前帧的额外实参区。
2. 调用 `beforeCall(position)`，写回 `liveAfter()` 为真的脏值。
3. 清空池的 `contents/homes/dirty`，不依赖被调用方保留 `$t3～$t8`。
4. 输出 `jal` 或 syscall；统一 `emit()` 同时清空工作寄存器缓存。
5. 如有使用者，将 `$v0` 中的返回值交给 `save()`，作为新的结果分配。

必须先放置参数再清空池，因为有些值恰好最后一次用于本次调用：它们不需要写回，却仍需要从当前 home 读出并传给被调用方。
CALL 之后继续使用的值则必须先写回，不能只留下将被调用方覆盖的池寄存器。
额外实参区与回退槽是分开的，写参数不会覆盖仍需保留的值。

条件分支先读出或计算条件，再调用 `spillLiveOut()`，最后输出跳转。
无条件分支和常量条件分支也在跳转前执行这个保存动作。
`spillLiveOut()` 只写回池中跨块使用的脏值，不会为了块内已经结束的结果写栈，也不立即清空映射。
进入后继块时，`locals.begin(block)` 才清空池；后继块从独立跨块槽读取这些值。

回写的实际指令只需要保存源 home 和合成地址的 `$t9`，不覆盖已经放在 `$t0～$t2` 中的分支条件。
RET 先读取返回值再跳到共同尾声，不需要保存其他即将随函数结束而消失的局部结果。

### 2.8 单一使用者比较及布尔链融合

**代码位置：**`MipsFunctionPlan` 中构造 `Comparison(instruction, inverted)` 的逻辑，以及 `MipsGenerator.branchComparison()`。

首先检查条件 BR 紧前方是否是 ICMP，分支条件是否正是该 ICMP 的结果，而且该结果只有一个使用者。
只有满足这些条件，才把比较延迟到 BR 处输出，避免改变其他消费者对这个结果的需求。

前端常见的条件并不是一条 ICMP 直接接 BR，而是：

```llvm
%a = icmp slt i32 %x, %y
%b = zext i1 %a to i32
%c = icmp ne i32 %b, 0
br i1 %c, label %yes, label %no
```

分析会从最靠近 BR 的比较反向检查：

- 当前谓词必须是 eq 或 ne，其中一个操作数已知为零。
- 另一操作数必须是 ZEXT，且扩展前的类型是 i1。
- ZEXT 的输入必须又是一条 ICMP。
- ZEXT 和更内层 ICMP 各只有一个使用者，且三条指令在原始块中相邻。

满足时把这一层加入 `fused`，继续向内检查。
`ne bool,0` 不改变真值；`eq bool,0` 表示逻辑取反，每遇到一层就翻转 `inverted`。
最终 `branches[br]` 记录真正需要的底层比较和整体方向。

生成器跳过 `fused` 中的独立指令；BR 查询记录，若 `inverted` 为真就交换 yes/no 目标。
这消除了中间布尔值的生成、掩码、搬运和回退槽，但没有把一般 i32 值错误地当作只含 0/1 的布尔值。
存在额外使用者、非相邻指令或不满足类型约束时，只融合安全的外层，或者完整保留原计算。

### 2.9 从谓词选择实际分支并保留远跳转能力

**代码位置：**`MipsGenerator.branchComparison()`、`signExtend()`、`jump()`。

方法先装入两个操作数。带 `s` 前缀的窄整数比较会先符号扩展；无符号比较保持零扩展后的位模式。
随后生成“条件为假时跳到附近辅助标签”的分支：

| IR 谓词 | 比较步骤 | 跳到假出口辅助标签的条件 |
| --- | --- | --- |
| eq | 直接比较两操作数 | `bne a,b,nearby` |
| ne | 直接比较两操作数 | `beq a,b,nearby` |
| slt / ult | `slt/sltu t,a,b` | `beq t,zero,nearby` |
| sgt / ugt | `slt/sltu t,b,a` | `beq t,zero,nearby` |
| sle / ule | `slt/sltu t,b,a` | `bne t,zero,nearby` |
| sge / uge | `slt/sltu t,a,b` | `bne t,zero,nearby` |

例如相等判断的控制流核心为：

```mips
bne $t0, $t1, nearby_false
nop
j yes_block
nop
nearby_false:
j no_block
nop
```

条件分支只需要跨过一个绝对跳转，而不是直接跨越可能很大的函数体，继续满足 16 位分支位移限制。
所有跳转仍通过 `jump()` 输出空延迟槽。这里没有为了少一个 nop 而依赖课程关闭延迟槽的设置，测试仍同时检查两种模式。

### 2.10 叶子函数删除返回地址槽和空栈调整

**代码位置：**`Frame` 优化分支的最后两项计算、`emitFunction()`、`addOffset()`。

第二轮把真实空间需求计算为：

```text
returnAddress = localBase + peak * 4
frameSize = align(returnAddress + (callsFunction ? 4 : 0), 8)
```

无普通函数调用时，不再额外加入 4 字节返回地址槽。
若其他区域也为空，`frameSize` 可以是 0。
`addOffset()` 在优化开启、偏移为零且源目标寄存器相同时直接返回，因此空函数不会再生成 `$sp += 0` 的入口和尾声指令。
调用普通函数的函数仍保留 `$ra` 槽和保存恢复；外部 syscall 不被当作会通过 jal 改写 `$ra` 的普通调用。

## 如何复核这些实现

### 从一条 IR 跟到最终汇编

阅读代码时可以选一条运行时 ADD：先看 `MipsConstants.get()` 是否能计算它；不能计算则进入 `arithmetic()`，先尝试 `selectArithmetic()`，再通过 `load()` 获取操作数。
计算完成进入 `save()`：先按位宽规范化，再调用 `locals.assign()`，必要时写回被驱逐值，最后把结果移入 home。
以后消费者通过 `load()` 优先使用仍在 home 或工作寄存器中的副本；如果跨过调用、基本块边界或发生驱逐，则使用已经更新的回退槽。

若这条 ADD 的右操作数是小常量，指令选择会变成 addiu，但后面的结果保存规则不变。
这说明“指令选择优化”和“结果存储优化”是分开的两层，可以分别观察和验证。

对于分支，应先读 `MipsFunctionPlan` 的融合识别，再看 `lastUses` 的构建，最后看 `emitInstruction(BR)` 如何选择常量跳转、融合比较或普通条件分支。
不能只查看 `branchComparison()`，否则容易遗漏它依赖的唯一使用者与生命周期条件。

### 回归入口具体检查什么

[run-mips-tests.py](../tests/run-mips-tests.py) 先以 `javac --release 17` 编译源码、界面管线和模型测试，再执行：

1. 在同一 JVM 中检查管线重复编译、成功失败交替、批量目录清理、命名稳定和输入 IR 不被修改。
2. 生成直接 IR 模型的普通版与优化版，分别在延迟槽开、关时运行；这些模型运行不计入 68×4 的用例计数。
3. 每个 SysY 用例分别编译 `--no-optimize` 和 `--optimize`，检查没有错误文件，并确认保留的 LLVM IR 一致。
4. 对每份汇编分别开关延迟槽，比较完整标准输出，仅统一平台换行，不忽略空格和末尾换行。
5. 检查汇编／仿真退出码、诊断输出和统计文件，并限制最大执行步数与宿主进程耗时。
6. 单独交替编译成功、语义错误和语法错误程序，确认 `mips.txt`、`llvm_ir.txt`、配置的优化前 IR 和 `error.txt` 不残留旧状态。

`tests/support/MemoryPreferencesFactory.java` 只用于测试时隔离 MARS 的用户设置，不属于提交编译器的运行依赖。
当前流水线不执行 LLVM IR 变换，因此脚本中的前后 IR 相等断言成立；将来加入真正的 IrPass 后，需要相应调整该断言，不能继续把文本相同作为优化正确性的条件。

## 当前实现边界

为了准确对应代码，后续介绍与答辩应区分以下几点：

- `MipsConstants` 是后端的纯整数常量分析，不是 SCCP，不会传播任意内存内容。
- `MipsFunctionPlan` 的 `crossBlock` 是保守使用关系，不是完整 CFG 活跃变量分析。
- `MipsLocalRegisters` 是块内寄存器分配，遇到块边界或调用会保存必要值，不是全局图着色或全函数线性扫描。
- 栈槽复用只覆盖后端内部结果的回退位置；还没有进行源程序局部变量的 mem2reg 或对象生命周期复用。
- `save()` 省略无人使用的结果保存，不代表一般死代码删除；常量条件也没有配套删除不可达块。
- 已实现的是特定常量乘法和 2 的幂除余，没有实现任意常量除数的乘法逆元变换，也没有做循环不变式外提、函数内联或尾递归消除。
