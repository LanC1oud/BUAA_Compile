# 文法驱动的批量测试生成器

工具位于 `testgen/`，使用 Python 标准库，不需要安装第三方依赖。它按文法推导生成输入，并独立计算编译器前端的预期结果；可选调用当前 Java 编译器逐个比较。生成器不会修改 `src/` 或项目根的 `testfile.txt`。

## 1. 快速使用

在项目根目录运行，需要 Python 3.10+。仅生成文件不需要 Java；`--check` 需要 JDK 17+。

```powershell
# 不新增规则，重点测试已有 EqExp，共 20 个完整程序
python -m testgen --count 20 --seed 42 --out build/generated-eq

# 直接输入产生式：会与已有 EqExp 合并去重，无需 // 前导
python -m testgen --rule "EqExp -> RelExp | EqExp ('==' | '!=') RelExp" --count 30 --out build/generated-eq-rule

# 添加前置、后置自增，与已有 UnaryExp 结合
python -m testgen --rule "UnaryExp -> '++' LVal | LVal '++'" --count 30 --seed 42 --out build/generated-inc

# 也可以从文件读取多条新增规则
python -m testgen --rules testgen/examples/inc.ebnf --count 30 --out build/generated-inc-file

# 穷举内置边界目录；基础文法目前有 39 个定向用例
python -m testgen --suite boundary --out build/generated-boundary

# 随机部分 30 个 + 基础边界 + 新增 ++ 专属边界
python -m testgen --suite mixed --rules testgen/examples/inc.ebnf --count 30 --scale 2 --out build/generated-inc-extremes
```

输出目录必须是新目录或空目录。所有生成工作成功后才写入批次；文法不合法或没有语义契约时，不会留下半批用例。默认输出位置是 `build/testgen-output`，再次生成请换一个目录。

若 PowerShell 的中文输出乱码，可以先执行 `$env:PYTHONIOENCODING='utf-8'`；生成的文件始终使用 UTF-8。

## 2. 产物结构与含义

```text
build/generated-eq/
├── effective.ebnf                 合并后的文法，可用于审查和再次生成
├── manifest.json                  参数、种子、候选式覆盖、文法产生式索引
├── case_0001/
│   ├── testfile.txt               完整 SysY 测试程序
│   ├── case.json                  此用例的种子、目标候选式、产生式使用情况
│   └── expected/
│       ├── lexer.txt              预期 token 序列
│       ├── parser.txt             预期解析输出／恢复后的解析轨迹
│       ├── symbol.txt             合法程序的预期符号表
│       ├── error.txt              预期最终错误；合法程序为空文件
│       ├── lexer.errors.txt       词法阶段预期错误；边界集含错误 a
│       └── parser.errors.txt      语法阶段预期错误
└── case_0002/ ...
```

错误用例不生成 `expected/symbol.txt`，因为课程驱动在有错误时应输出错误，而不是符号表。`case.json` 的 `stage_outputs` 指明各阶段应选择哪个预期文件；语法错误时，阶段正式产物应是 `error.txt`，其内容对应 `expected/parser.errors.txt`。此时保留的 `expected/parser.txt` 是恢复后的解析轨迹，供精细检查使用。

`main` 和运行时库函数不进入预期符号输出，作用域编号按进入顺序分配，排序按作用域编号及声明顺序，沿用当前项目的输出约定。parser 输出默认省略 `<Decl>`、`<BType>`、`<BlockItem>`。

这里的预期结果专指编译器前端结果。导入官方包时，会另外保留其 `in.txt`/`ans.txt` 为 `input.txt`/`output.txt`，但目前不执行程序或比对运行时输出。

官方错误库只提供 `error.txt` 时，生成器也只断言该答案，不伪造其它阶段预期。新增文法的非法形状若没有通用错误码，只提供 lexer 预期，并在 `case.json` 标明 `expected_outcome: syntax-rejection`，要求解析阶段拒绝；不会生成假的 `error.txt`。

## 3. 如何让输入有结构、有检测价值

完整程序模式是默认模式 `--mode program`。以下步骤描述默认的 `--suite random` 部分：

1. 加载 `testgen/sysy.ebnf`，合并新增规则。
2. 轮流指定目标规则的顶层候选式，使用固定种子的伪随机数展开其余结构。
3. 计算非终结符的最小终止深度，控制直接／间接左递归、可选项和重复项，避免无限展开。
4. 把表达式放入真实的 `if` 条件；把语句放进 `while (0)` 的语句块，保证 `break`、`continue` 有合法上下文。
5. 提供已声明、已初始化的 `int` 变量 `x/y/z`、常量 `k`、数组 `arr` 和参数个数确定的 `fn0` 等辅助函数；绑定变量、数组和函数调用的标识符。
6. 使用独立语义模型筛选基本类型混用、常量修改、调用参数、数组下标类型、控制语句上下文等问题。
7. 独立参考解析器重读最终程序，计算预期 token、语法树输出和符号表。

这不是原有全部 SysY 语义的第二套完整编译器。完整程序模式采用受控的、以 `int` 为主的测试子集；不承诺数组下标运行时安全、没有算术运行时错误或没有副作用求值顺序争议。它服务于词法、语法、符号表和静态错误检查，不生成运行时正确性保证。

随机部分的 `--count` 至少应等于目标规则顶层候选式数量，才能轮到每个候选式。`manifest.json` 现在分开记录调度次数和独立参考树实际使用的产生式，并列出未覆盖候选式。内部 EBNF 组合、语义和路径仍可能遗漏；全覆盖顶层候选式不等于整个语言完备。终结符使用次数另存于 `coverage.actual_terminal_uses`，便于检查 `==` / `!=` 等内部选择是否真正出现。

例如只生成新增的前置或后置自增，已有四个 `UnaryExp` 候选式，合并后新增项分别排第 5、6：

```powershell
python -m testgen --rules testgen/examples/inc.ebnf --alternative 5 --count 20 --out build/inc-prefix
python -m testgen --rules testgen/examples/inc.ebnf --alternative 6 --count 20 --out build/inc-postfix
```

单个用例的种子是批次种子加从 0 开始的用例序号。用 `case.json` 中的 `seed`、`alternative`、原文法和其余参数，可通过 `--count 1 --seed ... --alternative ...` 单独重现。

## 4. 支持的文法输入

直接输入产生式即可，不需要 `// ` 前导。支持以下写法，终结符必须加引号：

```text
EqExp -> RelExp | EqExp ('==' | '!=') RelExp
UnaryExp → '++' LVal
          | LVal '++'
Example ::= '(' Exp ')' [';'] {',' Exp}
```

- `->`、`→`、`::=` 均可。
- `|` 表示候选式；`(...)` 分组；`[...]` 可选；`{...}` 重复。
- `Ident`、`IntConst`、`CharConst`、`StringConst` 是内置词法类别。
- 允许直接和间接左递归，保留左递归语法树，用于比对解析输出。
- 兼容从源码注释复制的旧格式和普通注释；终结符引号中的 `//` 不会被当作注释删除。
- 默认合并同名规则并去重；使用 `--replace` 时替换输入中出现的同名规则。
- 引用未定义非终结符、不能终止的推导、未知 token 输出名会明确报错。

`testgen/sysy.ebnf` 根据仓库中的 2026 文法整理，去掉了中文说明和覆盖要求。它是生成器的基础文法；课程文法变化后需要同步它，或用 `--base` 指定新的 EBNF 文件。

## 5. 新运算符的词法名与语义契约

**文法能描述结构，但不能自动推出任意新规则的类型、符号和错误语义。**

生成器预置了现有终结符输出名，以及 `++ -> INC`、`-- -> DEC`。`++`／`--` 的内置语义契约限定为直接作用于可修改的基本类型 `LVal`，支持前置、后置；常量目标会被筛掉。其 AST 规则与前面的自增扩展方案一致，普通单目运算符的相邻限制仍然存在。

对于其他新终结符，使用 `--tokens` 指定它在词法输出中的名字。对于新的二元运算符，使用 `--semantics` 指定其类型契约，例如仓库提供的幂运算示例：

```powershell
python -m testgen --rules testgen/examples/power.ebnf --replace --focus PowerExp --tokens testgen/examples/power-tokens.json --semantics testgen/examples/power-semantics.json --count 20 --out build/generated-power
```

`power-tokens.json`：

```json
{"**": "POW"}
```

`power-semantics.json`：

```json
{"operators": {"**": "same"}}
```

`same` 要求两侧是相同基本类型，结果沿用该类型；`int` 同样要求相同基本类型，结果为 `int`。内置 `&&`、`||` 另允许不同的基本类型操作数。这只定义类型检查，不定义幂运算的运行时求值。

单个子表达式外包固定终结符的新节点，如果类型完全沿用子表达式，可以显式加入 `"transparent": ["NewNode"]`。增加新声明、作用域、复杂语句或其他类型规则时，需要在 `testgen/oracle.py` 增加相应语义处理；仅填写文法不能获得可靠的符号表和错误预期。未知语义会报错停止，不会自动调用待测编译器来“猜答案”。

引入新的 AST 层时，默认会在 parser 预期输出中出现 `<NewNode>`。如果你的实现省略该层，使用 `--hide NewNode`；这也是输出约定的一部分，不能只根据 BNF 决定。歧义文法由参考解析器选择一棵推导树；与手写解析器采用不同消歧策略时，需要先明确规则和输出约定，不能直接把所有差异判为编译器缺陷。

## 6. 任意规则片段模式

尚未定义语义、无法嵌入完整程序的新规则，可以先生成文法片段：

```powershell
python -m testgen --mode syntax --rule "Pair -> '(' IntConst ',' IntConst ')'" --count 10 --out build/generated-pairs

# 也可从完整基础文法推导整个编译单元，但此模式不保证语义合法
python -m testgen --mode syntax --focus CompUnit --count 10 --depth 24 --out build/generated-syntax-units
```

此模式的 `testfile.txt` 可能是片段；只提供 lexer/parser 预期，不生成 `symbol.txt` 或 `error.txt`，不支持 `--check` 或错误注入。若新规则含新终结符，仍需配置 `--tokens`。片段应交给对应的解析入口，而不能一律当作完整程序交给 `Compiler.main()`。

默认完整程序模式支持表达式链，以及 `Stmt`、`Block`、`BlockItem`、`Decl`、`VarDecl`、`ConstDecl` 等可嵌入语句的目标。其他目标若不能嵌入，会提示改用片段模式；不会悄悄丢弃目标规则。

## 7. 定向错误与错误恢复

先生成合法完整程序，再在独立一行注入一个已知错误：

```powershell
python -m testgen --negative mixed --count 18 --out build/generated-errors
python -m testgen --negative h --count 10 --out build/generated-const-errors
```

| 参数 | 注入内容 | 预期阶段 |
| --- | --- | --- |
| `c` | 未定义名称赋值 | 语义 |
| `h` | 修改常量 `k` | 语义 |
| `e` | `int` 变量接收 `char` | 语义 |
| `m` | 循环外 `break` | 语义 |
| `d` | 给无参函数传参 | 语义 |
| `l` | printf 格式参数数量不匹配 | 语义 |
| `i` | 赋值语句缺分号 | 语法及恢复 |
| `j` | printf 缺右圆括号 | 语法及恢复 |
| `k` | 数组下标缺右方括号 | 语法及恢复 |
| `mixed` | 按以上顺序轮换 | 每个用例一个错误 |

随机部分的错误注入仍限以上 9 类。新增 `--suite boundary` 定向目录覆盖完整 `a`～`n`，包括非法单个 `&`/`|`、重名、缺少返回值、重复 case/default、同一行错误优先级、多行 `i/j/k` 恢复。错误行号从最终源文件计算。

## 8. 与当前编译器比较

```powershell
# PATH 必须提供 JDK 17+，也可以显式指定安装目录
python -m testgen --count 30 --out build/generated-check --check --jdk 'C:\Program Files\Java\jdk-21'

# 不重新生成，保留输入，检查修复后的编译器
python -m testgen --check-only --out build/generated-check --jdk 'C:\Program Files\Java\jdk-21'
```

校验时只额外编译 `src/` 与 `testgen/java/CompilerProbe.java`，构建产物放在 `build/testgen-check/`，不调用会 `System.exit()` 的 `Compiler.main()`。同一 JVM 中逐个用例清空错误表和符号表；实际产物写入各用例的 `actual/`。重复校验会先清除桥接工具自身的旧产物，防止读取上一次的成功结果。

比较结果位于批次根的 `check-report.json`，内容差异另外写为对应的 `*.diff`。仅忽略文件末尾换行差异，保留其他字符差异。返回码：`0` 成功；`1` 当前编译器与独立预期不一致；`2` 文法、参数、输出路径或构建等工具运行问题。

报告包含逐用例名称、来源类型、通过情况及汇总。语法拒绝用例只接受解析阶段的 `IllegalStateException`，或明确的新增解析诊断；词法错误、语义错误、空指针及栈溢出均不能代替语法拒绝。此约定适配当前解析器的异常接口，不表示所有非法程序已有结构化诊断。

新增 `++` 等规则尚未落实到编译器时，`--check` 出现差异是预期现象。先生成批次、修改编译器，再用 `--check-only` 回归同一批输入。

生成器自身测试：

```powershell
python -m unittest testgen.test_testgen testgen.test_boundaries -v
```

本次验证包括 EBNF 解析、左右递归与终止、重复次数上限、种子复现、新规则合并与替换、token 最长匹配、未知语义拒绝、错误行号、输出目录保护，以及对现有 Java 编译器的批量比对。待测编译器仅参与实际结果的计算，不参与预期结果的计算。

## 9. 官方样例、边界与压力测试

`--suite` 控制生成策略：

| 参数 | 行为 |
| --- | --- |
| `random`（默认） | 保留原有随机推导，`--count` 控制数量 |
| `boundary` | 生成全部适用的固定边界；`--count` 不截断目录 |
| `mixed` | `--count` 个随机用例 + 全部适用边界 |
| `official` | 只导入 `--official-zip` 指定的官方包 |

任何完整程序套件都可以附加多个 `--official-zip`。ZIP 仅按数据读取，不解压或执行包内内容。每个官方原例默认附带一个变体，`--official-variants 0` 只导入原例，上限为 10。

```powershell
python -m testgen --suite mixed --count 40 --seed 20261022 `
  --official-zip 'C:\Users\96330\Downloads\2026语义分析作业公共测试程序库-错误程序库.zip' `
  --official-zip 'C:\Users\96330\Downloads\2026语义分析作业公共测试程序库-A.zip' `
  --official-zip 'C:\Users\96330\Downloads\2026语义分析作业公共测试程序库-B.zip' `
  --official-zip 'C:\Users\96330\Downloads\2026语义分析作业公共测试程序库-C.zip' `
  --out build/official-and-boundary
```

该组合生成 257 个用例：40 个随机、39 个基础边界、89 个官方原例、89 个官方变体。加入 `--check --jdk 'C:/Users/96330/.jdks/openjdk-24.0.2+12-54'` 可对照当前编译器。

官方变体统一重命名用户标识符，并在源文件前添加注释和空行；同步更新 `IDENFR`、符号表名称和错误行号，保持字符串、字符、注释和运行库名字。其预期从官方答案变换得出。`case.json.provenance` 记录压缩包、成员路径、原文件 SHA-256 和变体编号。原例和变体均不计入独立解析树的产生式覆盖，避免把未测量的覆盖算成已覆盖。

`--scale 1～4` 调整压力边界，和随机部分的 `--depth/--repeat` 分开：

| 内容 | scale=1 | scale=4 |
| --- | ---: | ---: |
| 表达式操作数 | 64 | 256 |
| 括号嵌套 | 16 | 64 |
| 作用域嵌套 | 8 | 32 |
| 函数形参 | 16 | 64 |
| 长标识符尾部字符 | 128 | 512 |

边界目录始终全部选择；`seed` 只改变其顺序。基础边界的符号表由独立声明/作用域遍历生成，错误答案由经过审查的模板显式约定，不调用待测编译器求答案。错误恢复参考先解析补全的程序，再删除缺失分隔符对应的 token；悬空 `else` 明确匹配最近的 `if`。

加入直接的 `UnaryExp -> '++' LVal | LVal '++'` 后，边界集从 39 个扩展到 115 个。新增部分覆盖类型、数组、常量、调用、返回、初始化、条件、循环、switch、printf、强转、遮蔽、最长匹配、注释间隔、非法目标和连写。`--` 可按相同直接 LVal 契约展开，但不会自动加入文法。常量上下文中的扩展错误 `o` 来自自增扩展文档，不是官方错误码。

自定义直接二元运算符在提供 `operators` 类型契约后，可推广整数边界、字符、混合类型、整个数组、结合方式、括号及缺少右操作数测试。工具会检查其可放在 `Exp` 还是只能放在 `Cond`；不能满足输入文法的组合会记录到 `boundary_limitations`。未知复杂新文法不会被声称已有专属边界策略。

覆盖标签、实际产生式与终结符、未覆盖项及限制都在 `manifest.json.coverage` / `boundary_limitations`。即使产生式全覆盖，也没有穷举类型交叉、任意深度、错误组合和运行路径；部分用例故意含越界或除零，用于验证前端接受行为，不能直接拿去执行。详细分析及已发现的差异见 [极端测试覆盖与官方样例分析](极端测试覆盖与官方样例分析.md)。
