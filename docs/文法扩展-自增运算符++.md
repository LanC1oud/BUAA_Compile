# 文法扩展方案：自增运算符 `++`

本文根据当前仓库代码整理，只说明应修改哪些文件、如何修改，未修改编译器实现。后续新增文法也可沿用本文的组织方式：明确规则 → 文件清单 → 分层改法 → 错误处理 → 验证用例。

## 1. 先确定扩展规则

当前代码只支持词法、语法、语义分析，中间代码和目标代码生成尚未实现（见 `src/utils/Controller.java`）。因此当前可完成的是识别、构建 AST 和语义检查；运行时更新变量属于未来代码生成阶段。

本文建议同时支持以下形式，属于本项目的扩展设计，并非现有课程文法要求：

| 形式 | 写回变量 | 表达式的值 |
| --- | --- | --- |
| `++i` | `i` 加 1 | 更新后的值 |
| `i++` | `i` 加 1 | 更新前的值 |
| `++a[k]`、`a[k]++` | 指定数组元素加 1 | 同样区分前置、后置 |

建议约束：

- 操作数限定为现有 `LVal`，即变量名或一维数组元素；不支持 `(i)++`、`++(i)`、`f()++`、`1++`、`++(i + 1)`。
- 目标必须是可修改的 `int` 或 `char` 标量，不能是常量、整个数组或函数。
- 结果类型沿用目标类型，以适配仓库现有的严格类型检查；`char` 更新时按现有无符号字符规则截断，即 `& 0xFF`。
- 前置、后置结果均作为普通值使用，不再次作为自增目标；拒绝 `++++i`、`i++++`、`++i++`。
- 自增具有副作用，不允许出现在要求编译期常量的上下文。
- 本方案不加入 `--`、`+=` 或 `for`，它们需要各自定义规则。

现有课程说明明确限制相邻相同 `UnaryOp`（例如 `++-i`）。加入独立 `++` token 后，这类连续字符的切分会变化。本文将 `++` 视为独立运算符，普通 `UnaryOp` 仍只有 `+`、`-`、`!`，原来的相邻相同普通单目运算符限制继续保留。正式实现前应将这项变化记入扩展规范，不能把它误认为原文法已有能力。

## 3. 词法分析：将 `++` 识别为一个 token

### 3.1 `src/frontend/token/TokenType.java`

在 `Plus("PLUS")` 附近增加：

```java
Inc("INC"),
```

`INC` 是本文建议的输出名称，并非原课程规定的 token 名称。

### 3.2 `src/frontend/Lexer.java`

当前 `+` 通过 `Symbols.TABLE` 的单字符映射识别，`++` 会得到两个 `Plus`。在 `readOp()` 的 `switch (c)` 中，增加专门分支，放在 `default` 之前：

```java
case '+' -> {
    int next = reader.read();
    if (next == '+') {
        addToken(TokenType.Inc, "++", start);
    } else {
        reader.unread(next);
        addToken(TokenType.Plus, "+", start);
    }
}
```

复用当前 `start` 记录首个 `+` 的位置。`Reader.unread(-1)` 已处理文件末尾，无需额外回退逻辑。`Symbols.TABLE` 的键是 `Character`，不能往里面添加字符串 `"++"`；保留原来的 `'+'` 映射即可。

采用最长匹配，只合并相邻字符：

| 输入 | 关键 token 切分 |
| --- | --- |
| `i++` | `Ident Inc` |
| `++i` | `Inc Ident` |
| `i + +j` | `Ident Plus Plus Ident` |
| `i+++j` | `Ident Inc Plus Ident`，即 `(i++) + j` |
| `i + ++j` | `Ident Plus Inc Ident` |
| `i+/*注释*/+j` | `Ident Plus Plus Ident`，不能跨注释合并 |

后续是否合法由语法、语义决定。例如原有“相邻普通单目运算符不能相同”的规则仍会拒绝 `+ +i`。

## 4. AST：保留前置、后置和目标信息

### `src/frontend/ast/expression/UnaryExp.java`

建议复用现有 `UnaryExp`，不额外增加非终结符节点：

1. `Kind` 增加 `PreInc`、`PostInc`。
2. 增加字段 `LVal target`、`Token incToken`。
3. 扩展私有构造器，现有 `primary()`、`call()`、`unary()`、`cast()` 为新增字段传入 `null`。
4. 增加工厂方法和 getter：

```java
public static UnaryExp preInc(Token incToken, LVal target);
public static UnaryExp postInc(LVal target, Token incToken);
public LVal getTarget();
public Token getIncToken();
```

以上是接口签名示意，需要配套实际方法体：前两个工厂分别创建 `Kind.PreInc`、`Kind.PostInc`，保存目标和 token，其余无关字段设为 `null`。

5. 在 `calculateConst()` 的 `switch (kind)` 中增加：

```java
case PreInc, PostInc -> throw new UnsupportedOperationException(
        "自增表达式具有副作用，不能进行编译期常量求值");
```

不能在这里调用目标的 `calculateConst()` 再加 1，也不能改符号表中的常量值。现有 `ConstFolder.fold()` 已捕获异常并返回 `null`，无需修改；但它不能代替语义阶段的错误报告。

`getName()` 保持 `<UnaryExp>`，继续兼容现有文本语法树输出。

## 5. 语法分析：接入现有表达式链

### 5.1 扩展后的文法

```text
UnaryExp → PrimaryExp
         | Ident '(' [FuncRParams] ')'
         | UnaryOp UnaryExp
         | '(' BType ')' UnaryExp
         | '++' LVal
         | LVal '++'

UnaryOp → '+' | '-' | '!'
LVal    → Ident ['[' Exp ']']
```

自增直接消费 `LVal`，因此自增目标不可能是另一个自增或一般表达式。`-i++` 会作为对 `i++` 的普通单目负号解析，`++i * 2`、`i++ + 2` 自然接入现有 `MulExp`、`AddExp`。

### 5.2 `src/frontend/Parser.java`：`parseUnaryExp()`

保留当前普通单目运算、强制转换和函数调用分支，按下面方式插入：

**在方法开头增加前置自增分支：**

```java
if (among(TokenType.Inc)) {
    Token op = consume(TokenType.Inc);
    LVal target = parseLVal();
    return watch(UnaryExp.preInc(op, target));
}
```

**在函数调用分支之后、当前最后一条 `return` 之前，增加标识符分支：**

```java
if (among(TokenType.Ident)) {
    LVal target = parseLVal();
    if (among(TokenType.Inc)) {
        Token op = consume(TokenType.Inc);
        return watch(UnaryExp.postInc(target, op));
    }
    return watch(UnaryExp.primary(watch(PrimaryExp.lval(target))));
}
return watch(UnaryExp.primary(parsePrimaryExp()));
```

函数调用分支必须在此之前，否则 `f(...)` 会先被当作变量。对于普通 `i` 和 `a[k]`，必须保留 `watch(PrimaryExp.lval(target))`，使原来的 `<LVal>` → `<PrimaryExp>` → `<UnaryExp>` 输出顺序保持一致。直接自增分支输出 `<LVal>` 与 `<UnaryExp>` 即可，与上面的新产生式一致。

### 5.3 同一文件：`atExpressionStart()`

在 `among(...)` 的 token 列表加入 `TokenType.Inc`。该方法实际用于：

- `parseReturnStmt()`：识别 `return ++i;` 中的表达式。
- `parseUnaryExp()` 的函数调用分支：识别 `f(++i)` 的首个实参。
- `parseVarDef()` 的数组长度入口：先允许解析，再由常量上下文语义检查拒绝自增。

只修改 `parseUnaryExp()` 会漏掉这些入口。

### 5.4 语句与回溯无需新分支

`i++;`、`++i;` 都能复用 `Stmt → [Exp] ';'` 和现有 `ExpStmt`。`isAssignStmt()` 试解析 `LVal` 后只有看到 `=` 才判为赋值；遇到 `Inc` 会恢复 token、错误表和 watcher，然后按表达式语句解析。因此不必新增 `IncStmt`，也不必修改 `parseLVal()`。

`consume()` 只为缺少 `;`、`)`、`]` 提供恢复；对于 `++1`、`f()++` 等本方案不支持的形式，当前框架可能抛出解析异常并中止，不能声称已经具有通用语法错误码。若要求这些输入也输出结构化诊断并继续解析，需要另行设计通用语法诊断与恢复，本方案不借用 `a` 或 `i` 冒充它。

## 6. 语义分析：自增既读取目标，也写回目标

### 6.1 `src/frontend/Traverser.java`

在 `analyzeUnaryExp()` 的枚举 `switch` 中增加：

```java
case PreInc, PostInc -> analyzeInc(exp, constContext);
```

增加 `private Type analyzeInc(UnaryExp exp, boolean constContext)`，建议按以下顺序实现：

1. 调用 `analyzeLVal(exp.getTarget(), false)`，复用名称解析、数组下标检查和 `LVal.setSymbol()`。这里使用 `false`，因为写入目标需要先正常解析；是否处于常量上下文由自增节点自己检查。
2. 取 `exp.getTarget().getSymbol()`；如果存在且 `isConst()`，在目标标识符处记录现有 `AssignToConstant`（`h`），并将该自增表达式视为非法。
3. 如果解析出的类型非空且 `!type.isBasic()`，在 `++` token 处报告 `MismatchedParameterType`（`e`），拒绝整个数组。函数误作变量、未定义目标和错误下标已经由 `analyzeLVal()` 处理。
4. 如果 `constContext` 为 `true`，在 `++` 处报告专用扩展诊断，禁止本节点成为常量表达式。
5. 常量修改、非标量目标或常量上下文检查失败时返回 `null`；目标类型非空且合法时返回该类型。现有 `put()` 会缓存结果并设置 `charResult`。

具体方法体如下，放在 `Traverser` 类中、`analyzeUnaryExp()` 方法之后即可。代码依赖第 4 节新增的 `getTarget()`、`getIncToken()`，以及第 6.3 节新增的 `ErrorType.InvalidConstantExpression`；现有 `Traverser.java` 已导入所需类型，无需新增 import。

```java
private Type analyzeInc(UnaryExp exp, boolean constContext) {
    LVal target = exp.getTarget();
    // 按本文 AST 工厂约定，target 和 incToken 均非 null。
    // 先按普通左值解析，常量上下文限制由本节点单独处理。
    Type type = analyzeLVal(target, false);
    SymbolVariable symbol = target.getSymbol();
    boolean valid = type != null;

    if (symbol != null && symbol.isConst()) {
        errors.add(ErrorType.AssignToConstant, target.getIdent().location());
        valid = false;
    }

    if (type != null && !type.isBasic()) {
        errors.add(ErrorType.MismatchedParameterType, exp.getIncToken().location());
        valid = false;
    }

    if (constContext) {
        errors.add(ErrorType.InvalidConstantExpression, exp.getIncToken().location());
        valid = false;
    }

    // 前置、后置具有相同的类型和合法性要求，取值区别留给代码生成。
    // 此处不修改变量值，也不做常量求值。
    return valid ? type : null;
}
```

这里不重复调用 `put(exp, type)`，由外层 `analyzeUnaryExp()` 统一完成。现有 `analyzeLVal()` 在部分下标类型错误后仍返回元素类型，因此该方法也可能返回非空类型，但错误表已经记录错误；返回类型用于后续分析，不代表整个表达式没有任何错误。同一行等优先级错误保留先记录的一条，例如常量目标的 `h` 会先于同一行的扩展错误 `o` 记录。

此检查只检查程序是否合法，不能在分析过程中真的给变量加 1。尤其 `i++;` 走的是 `ExpStmt`，不会进入 `analyzeAssign()`，所以不能只依赖后者已有的 `h` 检查。

`checkConsecutiveUnary()` 仍处理现有普通单目运算符，不要把自增节点伪装成 `Kind.Unary` 或给它填普通 `UnaryOp`。

### 6.2 同一文件：`lineOf()`

在处理 `UnaryExp` 的枚举 `switch` 中增加：

```java
case PreInc, PostInc -> unary.getIncToken().location();
```

新增 `Kind` 后，`UnaryExp.calculateConst()`、`Traverser.analyzeUnaryExp()` 和这里都是必须补全的穷举 `switch`，遗漏会导致 Java 编译失败。

### 6.3 常量上下文的扩展错误

现有错误码 `a`～`n` 没有专门表示“带副作用表达式不能用于常量上下文”的类别。本文建议在扩展版本的 `src/error/ErrorType.java` 增加：

```java
InvalidConstantExpression("o"),
```

这是新扩展约定，不能当作原课程错误码。`priority()` 已有 `default`，可沿用默认优先级；`ui/compilerui/model/DisplayError.java` 的 `chineseDescription()` 必须增加对应分支，例如“常量表达式中存在非法操作”。

若仍需提交原课程评测，应保留原规范版本或使用独立扩展开关，不应擅自让评测输出出现新错误码。未定义目标仍报 `c`，常量修改仍报 `h`，非标量目标报 `e`；同一行多错误的最终输出由现有错误表策略决定。

## 8. 未来代码生成阶段的要求

当前没有可以直接修改的 IR 生成器文件，下面仅是未来实现约束：

```text
address = 求目标地址（只求一次，包含数组下标的求值）
old = load address
updated = old + 1
若目标为 char：updated = updated & 255
store updated, address
前置自增返回 updated；后置自增返回 old
```

不能简单把 `i++` 替换为 `i + 1`，因为必须写回变量；也不能只替换成赋值语句，因为表达式还要产生正确结果。

对 `a[i++]++`，必须只求一次下标，使用原来的 `i` 定位元素，同时让 `i` 只增加一次。`&&`、`||` 的右侧若被短路，里面的自增不能执行。未来还应定义表达式操作数的求值顺序；当前不要用 `i++ + ++i` 这类样例作为运行时数值验收依据。

## 9. 实现后的验收用例

以下是待实现后的验收要求，本次仅编写文档，未实现或运行这些用例。片段中的变量应放在合法函数和声明环境中；各错误用例独立测试，避免同一行错误被合并。

| 场景 | 片段 | 预期 |
| --- | --- | --- |
| 单个加号 | `i + 1` | 仍识别 `PLUS` |
| 前置、后置 | `++i; i++;` | 识别两个 `INC`；两个 AST 形态不同 |
| 普通表达式输出回归 | `i + a[0]` | 原有 AST 层次与 watcher 输出不变 |
| 实参入口 | `f(++i)` | 正确识别首个实参；使用匹配的函数声明 |
| 返回入口 | `return ++i;` | 正确解析；函数返回类型与 `i` 一致 |
| 数组元素 | `a[k]++; ++a[k];` | 合法标量元素可修改 |
| 未定义目标 | `unknown++;` | `c` |
| 常量目标 | `const int c = 1; c++;` | `h` |
| 常量数组元素 | `const int a[1] = {1}; a[0]++;` | `h` |
| 整个数组 | `int a[2]; a++;` | `e` |
| 下标类型 | `int a[2]; char k = 'a'; a[k]++;` | 沿用现有下标必须为 `int` 的检查，报 `e` |
| 常量初值 | `int i = 1; const int n = ++i;` | 扩展错误 `o`，不能折叠出合法常量 |
| 数组长度 | `int i = 1; int a[++i];` | 扩展错误 `o` |
| 非法目标 | `++1; (i)++; f()++;` | 本方案语法拒绝；当前框架不保证通用错误恢复 |
| 重复自增 | `++++i; i++++; ++i++;` | 本方案语法拒绝 |
| 缺少分号 | 单独一行 `i++` 后接 `return 0;` | 保持缺分号错误 `i` 及原有恢复行为 |
