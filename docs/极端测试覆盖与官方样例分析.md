# 极端测试覆盖与官方样例分析

验证日期：2026-10-22。此次修改扩展独立生成器 `testgen/`，未修改编译器 `src/` 或 UI。使用方法详见 [文法测试生成器](文法测试生成器.md)。

## 1. 官方库提供了哪些基准

| 官方包 | 原始用例数 | 已提供的答案 |
| --- | ---: | --- |
| A | 20 | lexer、parser、symbol，以及运行时输入/输出 |
| B | 20 | 同上 |
| C | 20 | 同上 |
| 错误程序库 | 29 | error（行号、错误码） |
| 合计 | 89 | 60 个合法程序、29 个错误程序 |

压缩包作为测试数据读取；包内文本、注释和文件不会作为工具指令执行。原始官方答案直接保留，不用当前编译器反向生成预期。错误库没有附带其它阶段答案时，只比较最终错误，不自行补出所谓官方 lexer/parser 答案。

合法库提供了递归、多参数与数组参数、静态变量、常量表达式、部分数组初始化、字符与强转、嵌套作用域、短路表达式和长程序等样例。错误库尤其有价值的组合包括：

- 数组/标量/字符/void 之间的类型冲突；数组下标为字符；switch 与 case 类型不一致。
- 重复变量、重复形参、形参与局部变量冲突、重复函数；同名遮蔽与真正重名的区别。
- 未定义、离开作用域、先使用后声明；函数参数数量与类型同时不对时的诊断。
- 常量标量与常量数组元素修改；printf 数量与类型错误。
- void 函数带值返回、非 void 裸返回、缺少末尾 return。
- 重复 case/default；switch 中 continue 与 while 中嵌套 switch 的区别。
- 一份程序包含多个错误、缺少 `;` / `)` / `]` 后继续分析。

官方库涉及 `b`～`n`，没有独立的 `a` 样例；内置边界目录另外补了单个 `&` / `|` 的词法恢复。官方库不含新增 `++`，不能将其通过率当成新增文法的覆盖率。

## 2. 扩展后的生成逻辑

现在可以组合三种来源，全部保留可审查的预期与来源元数据。

| 来源 | 输入如何产生 | 预期如何产生 | 主要价值 |
| --- | --- | --- | --- |
| 随机推导 | 指定候选式 + 有界文法展开 + 受控语义筛选 | 独立 tokenizer、Earley 解析器、受控语义模型 | 探索结构组合，种子可复现 |
| 定向边界 | 经过审查的完整程序模板，全部选择 | 模板明确错误契约；独立解析/恢复和作用域遍历 | 稳定覆盖已知边界及其诊断 |
| 官方原例/变体 | 原例；一致重命名并前置注释/空行 | 官方答案；对名称和行号做同步变换 | 对照权威基准，检查名称与行号依赖 |

官方变体保护字符串、字符、注释、运行库名字；同步修改 lexer/parser 的 `IDENFR`、符号表名称、错误行号。原始运行时输入输出会保留，但不会执行或验证。重命名和插入空行属于等价变换，能检查位置/名字处理问题，**不会自动增加新的语义分支**。

边界模板的符号输出只做声明与作用域投影；模板的合法性和错误码来自显式的课程/扩展契约。它不是另一套完整的任意程序语义分析器。新增不认识的语义不能依赖这个投影来“证明正确”。

## 3. 基础文法的 39 个边界用例

| 维度 | 覆盖内容 |
| --- | --- |
| 数值/类型 | 0、1、int32 最大值、以表达式构成的最小值；char 的 0/127/128/255/256/-1 强转；负除法表达式 |
| 字符/字符串 | 全部项目支持的转义、空串、字符数组、常量字符串初始化、printf `%d/%c/%s` |
| 词法 | 长标识符、跨行/行末注释、运算符与注释相邻、空白隔开的单目运算、CRLF、tab、无末尾换行、EOF 行注释 |
| 表达式 | 优先级、括号、左结合长链、全部关系/逻辑运算符、短路形式、带调用的条件 |
| 声明/数组 | 多变量声明、static、长度 1、部分/空初始化、常量表达式长度、首尾元素、数组参数 |
| 作用域/调用 | 全局与局部遮蔽、嵌套遮蔽、递归、void/char 函数、零/多参数、先使用后声明、离开作用域 |
| 控制流 | 空语句/空块、悬空 else 匹配最近 if、嵌套 while/switch、break/continue、字符 case、空 switch、贯穿 |
| 错误 | `a`～`n` 全部 14 类；同一行错误优先级；多行分隔符错误恢复 |
| 压力 | 表达式、括号、作用域、形参数、标识符长度，提供四档规模 |

压力默认与最高档如下，档位之间线性增加：

| 参数 | scale=1 | scale=4 |
| --- | ---: | ---: |
| 表达式操作数 | 64 | 256 |
| 括号嵌套 | 16 | 64 |
| 作用域嵌套 | 8 | 32 |
| 形参数 | 16 | 64 |
| 标识符尾部长度 | 128 | 512 |

边界测试不依靠随机“碰到”这些情况；每次都生成全部适用项。`seed` 只改变边界目录顺序；随机部分仍用原来的逐用例种子。`--count` 只控制随机部分。

## 4. 新增文法的推广：以 ++ 为例

输入 `UnaryExp -> '++' LVal | LVal '++'` 后，自动识别直接 LVal 的前置/后置形状，额外生成 **76 个用例**，加上基础边界共 **115 个**。只输入前置规则时，不生成后置测试。

| 维度 | 专属边界 |
| --- | --- |
| 目标 | int、char、整数/字符数组元素、首尾元素、变量下标、下标自身带自增 |
| 上下文 | 表达式语句、优先级/普通单目运算、初始化、实参首项、return、if、while、switch、printf、强转、同名常量被局部变量遮蔽 |
| 值的边界 | int32 极值、char 255；只检查前端类型与语法，不断言更新后的运行时值 |
| 语义错误 | 常量标量/字符/数组元素 `h`；未定义 `c`；整个数组、函数目标、字符下标、结果类型不匹配 `e` |
| 常量上下文 | 常量初值、数组长度中的自增，使用扩展契约 `o` |
| 词法结合 | `x+++y` 最长匹配、token 之间插入注释 |
| 非法目标/连写 | `++1`、`1++`、`++(x)`、`(x)++`、`++(x+1)`、`f()++`、`++++x`、`x++++`、`++x++`、缺少目标等 |

其中 **17 个**是语法拒绝用例，提供精确 lexer 预期，要求 parser 拒绝，但不规定课程没有定义的通用语法错误码。只接受解析阶段的正常拒绝接口或解析诊断；NullPointerException、StackOverflowError 等不算成功。若输入文法本来就允许某种连写，会在覆盖限制中说明，不再强行把它标为非法。

这些约定与 [自增扩展文档](文法扩展-自增运算符++.md) 一致。`o` 属于此前提出的扩展错误，**不是官方 `a`～`n` 的一部分**。未来采用不同扩展语义时，应同时修改契约与参考用例。

同形状的 `--` 可复用边界策略，但只有显式输入该文法才启用。提供 `operators` 类型契约的直接二元规则，也能推广整数/字符/混合类型/数组操作数、结合、括号、缺少右操作数等边界；不适用的表达式组合会明确列入 `boundary_limitations`。新增声明、复杂语句或作用域规则仍需专门设计，不能仅靠一条 BNF 推出语义预期。

## 5. 本次实测

生成器自动化测试：**30 项通过**，覆盖原有推导逻辑及官方答案变换、字符串/注释保护、错误行号、作用域与数组参数、最近 if 消歧、全部错误类别、前置/后置与自减契约、新二元运算符表达式/条件上下文等。

当前核心编译器的组合回归采用 `seed=20261022`、`scale=4`：

| 类型 | 数量 | 结果 |
| --- | ---: | --- |
| 随机合法程序 | 40 | 40 通过 |
| 基础边界 | 39 | 38 通过，1 个返回值诊断差异 |
| 官方原例 | 89 | 88 通过，错误库第 19 例有差异 |
| 官方变体 | 89 | 88 通过，对应第 19 例的变体有差异 |
| 总计 | 257 | **254 通过，3 个用例存在差异** |

本地已生成批次：`build/testgen-validation-20261022/`，报告为其中的 `check-report.json`，差异分别在 `case_0054`、`case_0116`、`case_0117` 的 `error.txt.diff`。报告按用例名称/来源记录差异，编译器核心未修改。

三例都涉及非 void 函数中的裸 `return;`：官方原例应在第 3、31 行报 `e`，当前编译器漏报。边界目录将其缩为 `return-errors`，应包含 `8 e`，实际缺少这一项。这是明确的待修复诊断差异；不会通过修改预期来让回归变绿。

该批次的 **79 个独立生成用例**，参考解析/恢复树实际覆盖基础文法 **67/67 个非合成产生式**，并出现全部文法终结符。178 个官方原例/变体没有重新解析，因此没有计入此统计。此计数排除 EBNF 内部合成节点，**不等于所有内部组合或语义条件全覆盖**。

`++` 边界另生成于 `build/testgen-inc-extremes-final/`，115 个用例、包含 17 个语法拒绝用例，参考树覆盖扩展后的 69/69 个非合成产生式。当前核心尚未实现 `++`，比较会出现大量差异，不能据此宣称扩展功能通过；该批次供实现后使用 `--check-only` 回归。

## 6. 覆盖统计应怎样理解

`manifest.json` 分开列出：

- `scheduled_focus_candidates`：随机部分请求过哪些候选式。
- `actual_focus_candidates` / `actual_production_uses`：最终独立参考树实际包含哪些产生式，错误恢复用例统计其恢复树。
- `covered_productions` / `uncovered_productions`：真实产生式的覆盖清单。
- `actual_terminal_uses` / `uncovered_terminals`：内部选择的符号是否实际出现。
- `tags`：目标类型、上下文、错误码、词法和压力维度。
- `measured_cases`：多少用例计入产生式覆盖。
- `boundary_limitations`（批次顶层）：无法自动推广的扩展及通用限制。

仍不能承诺覆盖“大部分所有可能的极端情况”。语言有无限嵌套和组合，目前没有穷举多错误优先级、全部相互作用、任意新语义或所有编译器执行路径；也没有做源码分支覆盖、编译器变异测试或失败输入自动缩减。

本工具验证词法、解析、符号和静态错误。短路、副作用、字符截断等用例仅检查前端接受行为，**尚不检查求值结果**。个别 `frontend-only` 用例刻意包含数组越界或除零，用于确认它们不是课程静态错误；不应直接拿去运行。未来若需要运行时 oracle，应增加独立解释器或可靠的执行参考，并先明确溢出、除零、越界与求值顺序的规范。

## 7. 修改文件与后续扩展位置

| 文件 | 修改内容 |
| --- | --- |
| `testgen/official.py` | 只读 ZIP、官方原答案、名称/行号变体、来源摘要、保留运行时输入输出 |
| `testgen/boundaries.py` | 基线/扩展边界目录、压力倍率、参考作用域投影、恢复 token 投影、最近 if 消歧 |
| `testgen/__main__.py` | suite/scale/official 参数、混合批次、实际覆盖统计、按阶段比较与汇总报告 |
| `testgen/java/CompilerProbe.java` | 记录发生异常的阶段和异常类型；支持识别预期语法拒绝 |
| `testgen/test_boundaries.py` | 新策略的独立参考回归测试 |
| `docs/文法测试生成器.md`、`README.md` | 使用方式与范围说明 |

以后添加新文法，应先定义类型、可修改目标、作用域和错误策略；在 `extension_fixtures()` 添加专属模板与边界标签，再验证合法/非法两侧。文法能解析只是第一步，不能把不认识的语义默认为正确。
